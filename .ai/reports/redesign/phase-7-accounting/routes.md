## State review

- Initial/interaction loading, pending fieldsets, disabled commands, validation, success refresh and generic confirmation/dismissal remain existing ResourceModel/CommandForm behavior. No broad form refactor; successful financial submissions and unsaved-change dismissal were not exercised against a live API.
- Populated, empty, error/recovery, journal drawer and four command drawers exercised in Chrome at widths 390/844/1024/1280/1440/1920, light/dark. No document overflow or page errors; detail lines do not vertically clip. Visual review: 1440 light overview and 390 dark journal.
- No search/no-result/filter state exists in this read API. No fabricated search controls. Large-data, concurrency, rollback, denied server writes, exhaustive keyboard/screen-reader and device testing remain outstanding.
- Existing accessible table, scroll-region, status, drawer, command/select and loading primitives reused. Read denial tests do not replace backend authorization tests.

Financial contracts and server behavior inspected in `packages/contracts/src/accounting.ts`, `packages/api-client/src/stage6.ts`, and `apps/api/src/accounting/{accounting.controller,accounting.service,accounting.repository,sources}.ts`. None changed.
