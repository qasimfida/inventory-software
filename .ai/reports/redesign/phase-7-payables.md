# Phase 7 — payables

## Inspected and changed

Completed only payables on `redesign/phase-7`; no commit or implementation tag. Inspected both PayablePanel implementations and consumers, existing purchasing redesign, shared forms/client/contracts, route permissions, and server payable controller/service/repository. Existing unrelated working-tree changes preserved.

- Supplier totals now use a comparative currency table; no cross-currency aggregation or client calculation.
- Invoice drawers separate supplier/invoice context, exact balances, uncredited returns and settlement/credit history. Known supplier and warehouse names are used; unresolved identities remain references.
- Balances use aligned minor-unit values. Negative outstanding remains supplier debt. History uses readable event names, business-timezone timestamps and explicit missing references instead of `Shift null`.
- Web collection toolbar groups existing warehouse, refresh and supplier reset; invoice actions are compact, named and tooltip-equipped. Native keeps touch-labelled actions and equivalent financial tables.
- Existing error/retry presentation is also visible in the invoice drawer. Empty financial history is explicit. Existing forms, permissions, busy/dismissal behavior, IDs, pagination and financial posting remain unchanged.

New components are **feature-local** PayableDetails and PayableEvidence on web/native; both compose existing common primitives. No shared primitive, dependency, API, schema, migration, permission, settings, cache or transaction code changed.

13 source/test/script/guide files created or modified, none removed: [manifest](phase-7-payables-changed-files.json). Only canonical guide changed: `docs/design-system.md`, DS-081. [Route/state coverage](phase-7-payables/routes.md) accounts for collection, filters, detail, settlement/refund/credit and history. Generated root route/component inventories refreshed. One earlier customer report directory link was corrected to a concrete validation log because the foundation checker rejects directory links; no customer source was changed.

## Behavior preserved

Characterization ran **before UI edits: 10 tests / 4 files passed**. Added coverage for exact positive/negative/zero outstanding, cash/payment/purchase permission combinations, full-credit cutoff and uncertain credit retry identity. Existing settlement retry and read-only panel checks retained.

Backend authorization, warehouse scoping, cash-shift requirement, settlement caps, return ownership, original-credit cap, audit and idempotency were traced and not edited. Financial evidence is still loaded from the authorized server response. Returning stock alone does not record credit or settle debt. No offline payable command introduced.
