# Phase 6 — customers

## Scope and outcome

Completed the customer presentation pass on `redesign/phase-6`, without committing. Web and Tauri share the web implementation; native has equivalent feature-local composition. Existing shared primitives were reused, not changed. No new dependencies, routes, schema, transport, settings, ledger or permission changes.

Inspected customer collection, profile forms, statement contracts, customer pricing, payment identity, retention, POS customer creation, route registration and both platform consumers. Characterization tests ran successfully before UI edits (5 tests). Existing unrelated working-tree changes were preserved.

- Customer details now include contact/address/notes, privacy, store/status and a distinct credit-policy summary.
- Receivables, cash payments, refunds, credits and latest customer-price periods use compact existing tables/native RecordTable instead of repeated detail blocks. Exact strings and currencies remain intact; timestamps use business timezone and identifiers are references.
- Added explicit missing-history and no-active-store states; shared loading/retry presentation and a real refresh tooltip. Details expose errors within the drawer as well as the collection. Retry performs a read, not a replayed mutation.
- Matched the screen heading to the route shell to avoid duplicate titles. Customer drawer description now describes review rather than implying an unsaved form.
- Existing list/grid, filters, bounded pagination, export shown records, profile/credit/payment/price forms, archive confirmation and retention location were retained.

## Limitations and follow-up

- Existing nested archive confirmation Escape can dismiss both confirmation and parent drawer. Cancel was verified and does not submit. No shared dismissal-rule change was made in this customer-only pass.
- Existing generic command forms retain their pending/dismissal/validation behavior; this pass does not claim to resolve all nested-form error-focus or duplicate-submit concerns.
- Server payment/credit/archive constraints, tenant denial, concurrency/rollback and real success feedback were not exercised without an isolated database. Characterization does not replace server integration qualification.
- Mock customer prices/payments/refunds are empty; populated financial tables and exact amounts are covered by component tests. No names or missing transactions fabricated.
- Windows build/runtime unavailable on this Mac. macOS installed WKWebView runtime, native simulators/hardware, screen readers, printing, offline vault and device keyboard/safe areas remain unverified. Customers/credit still require online authority.
- Both CustomerPanel controllers remain over the review threshold; presentation extraction keeps new components small and retains cohesive request/command ownership. Existing scoped exception rationale remains applicable.
- Initial type checks caught test-only `exact` options and possibly undefined form values, corrected without production changes. Initial browser attempt was invalidated by build HMR; another exposed nested Escape behavior; grid assertion initially used visible text instead of its accessible name. Failure logs are retained; final corrected run passed.
