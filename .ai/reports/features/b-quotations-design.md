## Decisions recommended for approval

1. **No stock reservation in v1.** Quote, send and acceptance do not change stock, cash, AR or journals. Availability is explicitly a dated informational snapshot, never a promise. Checkout still enforces current inventory rules.
2. **Snapshot prices, discounts and tax treatment per revision.** Explicit Refresh prices displays server-generated old/new differences and requires confirmation before replacing draft values. Sent/accepted documents are immutable; Revise first. Never silently refresh a previously sent quotation.
3. **Honor an accepted, unexpired, current revision only with `quotations.convert` plus `quotations.override` when historical prices differ from current pricing.** Server reads the snapshot; clients cannot submit arbitrary honored prices. Unauthorized/expired changes require a new revision and acceptance, not a hidden repricing at checkout.
4. **Number per business + store, e.g. `Q-{storeCode}-000001`, with a monotonically increasing sequence and no annual reset in v1.** Freeze prefix/store code on allocation. Revisions display `… / R2`, using one quotation number. Duplicate creates a new number. No legal gap-free numbering claim.
5. **One shared typed document representation and three code-defined templates; recommend centralized PDF rendering for consistent downloadable output.** This adds a production renderer/deployment prerequisite requiring approval; compare alternatives below.
6. **Online-only quotation writes and conversion.** No new quotation persistence in the offline vault and no offline credit/conversion. An unsaved in-memory draft remains visibly unsaved while temporarily disconnected, within session limits.

## Data model

Use additive, tenant-scoped tables with composite foreign keys; no changes to historical sale/ledger amounts.

- `quotations`: UUID, businessId, storeId, **warehouseId** (required in v1 to preserve warehouse-tier isolation), immutable number/prefix/sequence, currentRevisionId, createdBy/createdAt, convertedSaleId nullable. Required warehouse avoids letting warehouse-restricted staff read every store quotation; the number sequence remains store-scoped.
- `quotation_revisions`: UUID, quotationId, businessId/storeId/warehouseId, revision ordinal, optimistic `version`, status `draft|sent|accepted|rejected|expired|converted`, customerId nullable, allowlisted customer/walk-in snapshot, issueDate, validUntilDate, business-timezone snapshot and derived expiresAt, currency, templateId/templateVersion/options, branding snapshot, notes/terms, subtotalMinor/discountMinor/netMinor/taxMinor/totalMinor (server calculated), quote fingerprint, calculation timestamp, createdBy, lifecycle timestamps, convertedSaleId nullable.
- `quotation_lines`: stable UUID, revisionId, tenant scope, product/variant/unit identifiers and name/SKU/description snapshots, selected-unit quantity, base-unit conversion snapshot, resolver base-unit price, displayed selected-unit price representation, source price/promotion IDs, override flag/reason/actor, discount basis points, tax basis points/inclusive flag, exact computed amounts, sort order, optional validated image reference/snapshot, informational availability + observedAt.
- `quotation_events`: append-only revision/state/change metadata, actor, time, safe reason and command ID, linked to the existing audit mechanism. Never delete old revisions or convert audit history into editable notes.
- `quotation_number_counters`: business/store key, next value and prefix configuration/version. Allocate inside the same authorized transaction as creation with atomic locking. Stable command replay returns the same number; don't use `MAX(number)+1`.

Constraints/indexes: unique business/store/sequence, quotation/revision ordinal, revision/line sort position, one converted sale per quotation family, tenant-qualified product/customer/unit references, positive exact quantities, bounded money and dates. Index list queries on business/store/warehouse + status/validity/issueDate/customer, plus bounded number/customer search. Keep maximum 50 lines in v1 to match POS conversion; the blank editor row is not a stored line. Duplicate/reordered lines retain their own identity and sort order.

Dates: business-local issue/valid-until dates, valid until the end of that local day. Store timezone and derived exclusive expiresAt at issuance so a later business timezone change does not silently alter validity. Server rejects validUntil before issueDate. No client-clock authority. Currency is one actual transaction currency; user display-currency preference is not FX.

Money: retain the resolver's base-unit price and conversion factor. Do not relabel it as a selected-unit price. Display a clear per-unit basis; if a selected-unit override cannot map exactly to supported base-price precision, reject it with guidance instead of silently rounding. Compute subtotal/discount/net/tax/total using the same exact math and documented inclusive-tax semantics. Tax cells are read-only in v1, inherited from resolver; tax overrides are a separate unapproved capability.

Branding/customer snapshots are frozen when sent, while drafts may explicitly refresh them. No passwords, tokens, private supplier costs or arbitrary HTML are stored in documents. Bank-details option requires typed public payment instructions configured by business writers; hide it when absent. Signature means a blank signature line, not an electronic-signature claim.

## Server state transitions

| From                                 | Command             | Result / rules                                                                                                                                                                     |
| ------------------------------------ | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| New                                  | Create              | Draft, number + revision 1, default template selected/confirmed; no stock/money effects.                                                                                           |
| Draft                                | Save/autosave       | Version-checked validated data; server totals returned. Version conflict preserves local edits for comparison.                                                                     |
| Draft                                | Mark sent           | Sent; requires valid completed document and current pricing snapshot. Records actor/time/method; does not pretend to email anything.                                               |
| Sent                                 | Accept / Reject     | Accepted / rejected, with actor and timestamp; staff records customer decision, not a fabricated customer signature.                                                               |
| Sent or accepted                     | Deadline reached    | Effective expired status in every query/action, even if no job has run; optional idempotent materialization event once. Expired cannot convert.                                    |
| Draft past deadline                  | Save / send         | Remains editable draft with expiry warning; sending requires a valid date.                                                                                                         |
| Sent / accepted / rejected / expired | Revise              | New current draft revision; original revision immutable, retains historical status/events and is shown as superseded metadata, not a new status enum. Old revision cannot convert. |
| Any readable                         | Duplicate           | New draft family/number; no acceptance/conversion link copied; resolve current prices and show differences.                                                                        |
| Accepted + current + unexpired       | Prepare conversion  | Opens prefilled POS; **does not** mark converted, reserve stock or post sale.                                                                                                      |
| Accepted + current + unexpired       | Successful checkout | Converted and linked sale atomically with stock/payment/AR effects; unique source-family guard prevents two sales from different command IDs.                                      |
| Conversion failure / abandoned cart  | None                | Quotation stays accepted; normal expiry continues. No hidden sale or completed conversion.                                                                                         |

Converted quotations cannot be revised into another sale of the same family; use Duplicate for a new sale proposal. Returns/voids do not reopen a converted quotation. Accepted terms/price changes always require a new revision and acceptance. All mutations, including autosave/lifecycle commands, use stable IDs and expected versions; no generic automatic write retries.

## API and shared-client proposal

Within the existing authenticated business API prefix:

- `GET /quotations`: bounded search/filter/status/customer/date, warehouse/store scope, offset pagination initially to reuse current collection contracts.
- `GET /quotations/:id`: current revision + permitted document metadata; separate bounded history/revision reads.
- `POST /quotations`: idempotent draft creation and number allocation.
- `POST /quotations/:id/revisions/:revisionId/save`: expected version + stable command ID + typed editable fields/line IDs. Ignores no client totals: reject unknown fields and recalculate on server.
- Read-only `POST .../price-preview`: resolves candidate prices and returns differences tied to revision version/fingerprint; no persistence. Confirming refresh uses a versioned command and revalidates current resolver results; if they changed again show a new diff.
- `POST .../send`, `/accept`, `/reject`, `/revise`, `/duplicate`: explicit authorized state commands, audit + idempotency receipt in the same transaction.
- `POST .../conversion-preview`: read-only validation/preparation with source quotation/revision/version/fingerprint and target warehouse. No financial effects. Existing POS model receives a typed source reference and authoritative lines, not trusted arbitrary prices.
- Extend existing POS quote/checkout contracts with an optional quotation source reference. Server rechecks current revision/status/expiry, source lines, scope, permission and snapshot/current-price policy; uses existing math then existing checkout effects. Snapshot price input is server-internal only. An ordinary POS cart without a source retains unchanged behavior.
- `GET .../document` for validated preview data and `GET .../pdf` for the frozen/rendered revision. Authenticated, rate/size/time bounded, private/no-store; no public share token or email sender in v1.

Conversion is one quotation → one sale, with exact accepted source lines and amounts. No partial conversion, combining quotations or adding unrelated cart lines in v1. Editing quoted quantities/unit/discount/customer prompts Revise; alternate ordinary POS sale can start independently but must not mark the quotation converted. Existing held carts must preserve/validate source identity on resume; unknown-outcome retry keeps the original source, payload and key. A new revision or expiry during payment rejects before posting.

A successful sale plus quotation linkage is one database transaction. Authorization precedes replay; uniqueness by quotation family prevents duplicate conversion even with two different keys/operators. Failed checkout rolls back link, status, movements and payments. Don't route quoted prices through the existing `onlineOverride` shortcut or `verifiedOfflineQuote` trust path.

## Permission proposal

Add `quotations.read`, `quotations.write`, `quotations.override`, `quotations.convert` to shared strict schemas, role defaults, assignment UI, server guards, audit and route parity.

| Role                                      | Recommended defaults                                                                                                                            |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Owner / authorized platform administrator | All four within explicit business context; never tenant-unbounded endpoints.                                                                    |
| Manager                                   | All four within assigned store/warehouse scope.                                                                                                 |
| Cashier                                   | Read, write, convert; no price/historical-price override. Requires existing sales/payment/customer permissions for those respective operations. |
| Viewer                                    | None by default; existing viewer does not have broad product/customer access.                                                                   |
| Custom                                    | Explicit assignment only; existing custom roles do not gain privileges by migration.                                                            |

Quotation write covers draft editing, marking decisions and revisions; override covers manual price/discount changes with required reason and honoring historical prices differing from current values. It does not grant product price-list editing, tax override, customer credit override or cash permissions. Conversion additionally requires `sales.write` and normal payment/credit permissions. Customer selection needs `customers.read`; product lookup needs `products.read`. Never send hidden customer PII, cost prices or broader warehouse data to populate options.

## Editor, list and detail UX

Routes proposed: `/quotations`, `/quotations/new`, `/quotations/:id` with preview/history inside the detail workflow. Add the shared navigation registry and matching native destinations; no inaccessible disabled sidebar links. Template picker is the first step with three real previews; changing it changes presentation only.

List: existing RecordCollection, search/status/customer/date filters, expiry warnings, permitted New quotation action, pagination and authorized exports. Show number, customer/walk-in label, issue/expiry, state, total/currency, revision. Details expose events, immutable older revisions and only valid lifecycle actions. Do not label a quotation “Paid”.

Web/Tauri editor: reuse Table/TableScroll styling with an explicit ARIA grid interaction layer. One roving tab stop; stable row IDs and cell focus; headings/row/column announcements; read-only computed cells. Enter/typing begins edit in the same cell. Enter commits and moves down; Tab/Shift+Tab commits and moves across; arrows navigate in navigation mode, while editable text/select controls retain normal editing behavior; Esc restores the prior cell value. Failed validation keeps editor/focus and associates errors. Ignore shortcut handling during IME composition. Product combobox captures its own arrows/Enter; selecting an option must not also commit a sale or move two cells.

Columns: No, Product, Description, Unit, Qty, Unit price, Discount, Tax, Total. Actual resolved price populates on selection. Blank trailing row opens bounded cancellable search; barcode resolves through existing product lookup. No fabricated rows/products. Keyboard Move up/down actions accompany optional dragging; duplicate/delete accessible row actions never silently merge quotation lines. Wide grids scroll within the named region, never the page.

Native: compact line cards with inline quantity/price editing, numeric keypad, product search and expandable description/discount/tax details. Preserve safe areas, keyboard avoidance, touch targets and screen-reader order. Tablet landscape may retain cards initially; do not import the DOM grid. Equivalent actions and exact totals are mandatory even where layout differs.

Autosave: debounce valid committed changes (proposed 750ms), serialize writes per draft, coalesce newer local edits behind the in-flight request. Show Unsaved / Saving / Saved at time / Save failed / Conflict. “Saved” means matching server version acknowledged, not timer completion. Invalid partial cell input stays local and unsaved. Reject stale responses; never cancel an in-flight mutation then assume it was not saved. On network uncertainty retry the identical command; never blind last-write-wins. A 409 shows remote/local comparison and explicit recovery. Navigation guard for unsaved/pending edits; no service-worker/private offline caching.

States: initial/interaction loading, new/empty/no-results/filtered/populated lists, failed lookup/calculation/save/export, permission denial, expired/inactive referenced product, stale revision, offline, pending mutation, success announcement, validation, unsaved changes, delete-line confirmation where needed. User theme/density/control size/font/radius/motion preferences apply to screens; print documents use accessible paper presentation and business branding rather than the operator's dark theme.

## PDF and print decision

| Option                                                        | Advantages                                                                                                             | Costs / limitation                                                                                                                                                                                             |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared typed document → escaped HTML/CSS → platform print     | Existing iframe and expo-print; no additional runtime dependency; easiest print support                                | Different engines paginate differently; browser Save as PDF depends on OS/browser and is not a guaranteed downloadable file. Does not fully meet consistent PDF/share acceptance.                              |
| **Shared typed document → server-rendered PDF (recommended)** | One PDF artifact for preview/export/share across clients; controlled fonts/templates/page breaks; no client PDF engine | Needs approved production renderer/browser dependency and deployment resources, bounded queue/timeouts and secured image ingestion. Current Playwright is dev tooling, not an existing production PDF service. |
| Client/native PDF libraries                                   | Can generate locally                                                                                                   | Duplicated renderers, font/layout drift, extra packages, larger clients; not recommended for v1.                                                                                                               |

Recommend server-rendered PDF using a pinned headless Chromium renderer after explicit dependency/deployment approval, with the same typed templates driving HTML preview. Reusing the repository's Playwright toolchain does not make shipping it in the API free: production packaging, browser binary updates, container isolation, concurrency and memory budgets must be approved. Do not install anything during design.

The renderer receives validated document data only, no user HTML/JS, arbitrary URLs or API credentials. Preload bundled fonts and sanitized bounded image bytes through authorized SSRF-safe media retrieval; disable renderer network access and script execution. Cap lines/media/document size, time and concurrency. Validate content types and URLs; missing images show a placeholder and export warning rather than exposing internal hosts or blocking text export. Store template version and frozen branding/text; immutable image bytes or content-addressed assets are needed for reproducible historical images. Snapshotting may require a small private document-asset store with explicit retention, never cache private documents publicly.

Three code-defined templates: Classic formal header/table; Modern compact minimal; Detailed optional product image/description blocks, terms and blank signature area. Typed options: images, SKU, tax column, signature, configured bank instructions, footer. Hiding tax columns never changes calculations; final tax/total summary stays clear. Repeat headers and keep totals/terms legible across page breaks. Default template per business; selection frozen per revision. No template HTML editor or external font CDN.

Web downloads authenticated PDF bytes; browser print adapter prints approved preview/document with honest capability fallback. Tauri uses supported host save/print behavior, verified on both OSes; no invented plugin capability. Native writes received PDF to an app-private temporary file then uses existing print/share adapters; clean up after use, never mark cancelled sharing as quotation rejection. External sharing is an explicit user action, not automatic email/SMS delivery.

## Migrations, risks and verification

Forward additive migration creates quotation/revision/line/event/counter structures and nullable sale-source linkage with uniqueness. Existing sales have no source; existing businesses get read-time default Classic options and store-specific numbering defaults, without rewriting user appearance preferences. New role permission defaults are tested; existing custom assignments remain unchanged. Rollback means disable quotation routes/writes and deploy a compatible reader while retaining all quotation/source data; no destructive down migration after records exist. Provide export/backup verification and a separate corrective forward migration if needed.

Primary risks: honoring historical tax/discount amounts against later policy, currency/unit rounding, scoped PII/media exposure, multiple conversion attempts, price changes between diff and save, autosave conflicts, revision acceptance/expiry races, stale held POS carts and unknown checkout outcomes. Recommend preserving full accepted financial snapshot until expiry; any tax-policy requirement for current rates must instead force revision/reacceptance and needs an explicit decision. No claim of legal tax compliance is implied.

Tests after approval: preserve current pricing/checkout characterization; add exact inclusive/exclusive tax and unit/override tests; state/expiry/timezone/DST/revision tests; numbering/idempotency/two-operator conversion concurrency; tenant/store/warehouse/custom-role denial; failed transaction rollback with no ledger/cash/AR side effects; historical snapshot conversion and source-line identity; autosave/unsaved/race errors; ARIA grid keyboard/IME/combobox behavior; native card controls; real template PDF page/asset/font tests; Playwright create→edit→send→accept→convert→receipt for cash/credit as authorized. Cover all three templates and failed export without changing status.

Run existing actual scripts for lint/typecheck/unit/isolated DB integration/parity/design checks, web/browser and mobile/desktop builds. Qualify Windows/macOS installed save/print, native emulator/device keyboard/share and peripherals separately. Current known Phase 10 Windows/native gaps and macOS packaging limitation are not solved by a quotation design. Mock fixtures must include all states, scopes, template variants and uncertain conversion.

Implementation order: characterization → additive contracts/data/permissions/numbering → immutable snapshots and lifecycle → autosave/shared model → grid/native cards → document templates/rendering → controlled POS conversion → cross-platform tests/docs. Coordinate Feature A's pending recovery/completion design, but do not assume its APIs are implemented or quietly implement its unrelated scope.
