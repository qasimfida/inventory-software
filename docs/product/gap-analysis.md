# Product feature gap analysis

Audit date: 2026-10-24. Scope: `docs/product/feature-spec.md`, sections A and B. This is a static repository audit, not a runtime certification. No application code, database, settings, seeds or security rules were changed. No builds, migrations or functional tests were run for this report.

## Milestone 1 decision addendum — 2026-10-24

The static statuses below remain implementation findings. [Accepted Milestone 1 decisions](../decisions/milestone-1.md) now supersede proposed remedies for ordered/sent metadata, deferred named price lists, reason codes, refund approvals/compensation, public API boundaries, sellable stock/backorders, readiness, payments/posting and analytics. In particular, A06's named-list gap is deferred, not a v1 implementation requirement. Analytics persistence is not planned for v1; use only bounded in-memory cached/as-of display. Reports' timezone/net-return behavior remains an implementation gap.

[Release qualification](../release/qualification.md) gates web, Windows and macOS; Android/iOS still require feature parity, with runtime qualification tracked separately. This supersedes any implication in the original backlog that mobile device qualification gates first launch.

Further configuration inspection qualifies the image-CSP finding below: the base Tauri config blocks remote images, but `scripts/desktop-profile.mjs` generates a broad `https:` image allowance. Neither proves trusted-host qualification; inspect the final merged artifact and narrow its media policy before release. No code changed with this addendum.

## Reading the results

- **Present**: an implementation and a reachable platform consumer were found for the stated capability. This does not certify correctness on real devices.
- **Partial**: some of the requirement exists, but named subrequirements are absent or materially narrower than the spec.
- **Missing**: no implementation was found in the searched source, contracts, migrations or routes. A plan, mock, dependency, placeholder or similarly named unrelated feature is not implementation evidence.
- Section A rows correspond to **all 26 checklist bullets**, in their original order. Subrequirements within composite bullets are explicitly distinguished. Unless a platform exception is stated, the subrequirement findings apply to all three platforms.
- Priority **M/S/L** means must/should/later from the spec. Backlog **effort S/M/L** means small/medium/large and is a separate dimension.
- Routes are application paths. Web uses hash navigation; native uses a logical route stack rather than a browser router.
- Desktop is the shared web frontend, not an independently reimplemented UI: `apps/desktop/src-tauri/tauri.conf.json` points `frontendDist` at `../../web/dist`. Each web evidence path below is therefore also desktop evidence, subject to native restrictions. Windows/macOS qualification is not inferred from shared code.

### Platform and route evidence

`packages/api-client/src/workspace-navigation.ts` defines shared route names and permission visibility. `apps/web/src/shell/WorkspaceScreens.tsx`, `apps/web/src/features/organization/workflow-panels.ts`, `apps/mobile/src/shell/NativeScreens.tsx` and `apps/mobile/src/organization/ManagementWorkflows.tsx` connect them to actual screens. Settings are dispatched by `apps/web/src/shell/SettingsPage.tsx` and `apps/mobile/src/shell/SettingsScreen.tsx`.

`docs/architecture/platforms.md` records macOS builds and limited runtime coverage, Android Expo/emulator coverage, absent Windows qualification and unavailable iOS native qualification. None was rerun here. Product-image HTTPS URLs are an additional desktop concern: the current Tauri CSP allows images only from `self` and `data:`; shared image markup alone does not demonstrate desktop remote-image support.
