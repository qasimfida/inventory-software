# Release qualification

Status: **plan and unchecked release gates**, 2026-10-24. No tests or builds were run for this document. [Platform status](../architecture/platforms.md) contains historical evidence; it is not a pass for a new release candidate. [Milestone 1](../decisions/milestone-1.md) defines approved behavior; unfinished features are not implied to exist.

## Scope and evidence rules

Web, Windows desktop and macOS desktop are launch-gated: every applicable item below needs evidence against the exact candidate. Android/iOS require feature parity in the same changes, but native qualification is tracked independently and does not gate these three launches. The public storefront is web-only; its management UI must retain native parity. Any parity blocker/follow-up belongs in [gap analysis](../product/gap-analysis.md), not an undocumented exclusion.

For every result record commit/source revision, artifact hash, configuration/profile, API/schema version, OS/CPU/browser or WebView version, device/peripheral model, role/scope, test date, operator, logs/screenshots and pass/fail/blocker. Do not store credentials, tokens, customer PII or vault passphrases in evidence. An unchecked item is unverified, not a pass. Declare the actual browser/OS/architecture support matrix before release; do not infer support from the host used to build.

Common runtime scenario: invite/login/logout/recovery and expiry; owner/admin/scoped manager/cashier/viewer navigation and denied API access; tenant switching/isolation; product/pricing updates; POS scan/cart/cash/credit/receipt; receiving/returns/counts/transfers; refunds/approvals when implemented; settings/themes/text scaling; notifications/error/retry; network loss, restart, revoked/expired grant, replayed sync and financial/stock reconciliation. Test actual available workflows, and list required but unimplemented behavior as a blocker rather than inventing a passing test.

## Web — launch-gated

- [ ] **Build/deployment:** reproducible `npm ci`, shared/API/web production build, validated HTTPS API/app origins, production mocks disabled, correct caching/security headers, immutable versioned assets and successful fresh deployment. API migrations are separately tested against disposable data and deployed through a controlled process, never by client startup.
- [ ] **Runtime smoke:** execute common scenario in each declared supported browser using the production bundle, not only Vite; check small/large viewports, keyboard/focus/screen reader, zoom and reduced motion; no unexpected console errors or unauthorized navigation.
- [ ] **Offline storage:** IndexedDB encrypted vault, wrong-passphrase/tamper rejection, account/origin separation, lease expiry, hidden-tab key erasure, multi-tab claims, quota/eviction handling, restart and backup/restore into an unused name. Prepared offline cash works after a production-shell reload; unprepared users are not granted offline access. Reconnect confirms each stable ID once and retains conflicts.
- [ ] **Printing:** browser receipt preview/cancel/reprint and supported Save-as-PDF behavior; no payment-state change on print failure. Record actual printer/paper/cutter limits; do not claim ESC/POS or cash drawer support from `window.print()`.
- [ ] **Links:** configured production HTTPS invitation/recovery links, refresh/direct navigation, malformed/expired/replayed links and account switching. Browser-to-desktop `inventory:` handoff, no-app-installed fallback and secret redaction; avoid auth tokens in analytics/referrers.
- [ ] **Remote media/CSP:** approved HTTPS image hosts display; disallowed hosts/content are blocked; image failure has a usable fallback; no mixed content, unrestricted proxy or internal-network image fetch. Test final deployment headers, not only source CSS/HTML.
- [ ] **Updates:** service worker waits safely during checkout; old/new bundle/API compatibility; rollback and cache-version migration without deleting outbox; no API/auth/analytics persistence by service-worker caching. Cached analytics is memory-only and expires/locks per D11.
- [ ] **Real hardware:** physical keyboard-wedge scanner, receipt printer and any advertised peripheral; network disconnect/reconnect, suspend/resume and storage-pressure behavior on supported browser/OS combinations. Automation cannot qualify print drivers or physical cash peripherals.

## Windows desktop — launch-gated

- [ ] **Build/installer:** native Windows MSVC/WebView2 build, locked Rust dependencies, signed selected MSI/NSIS installers, certificate/timestamp verification, clean install/upgrade/uninstall under standard user and required permissions. Test each advertised CPU architecture. Existing `.app` or web build is not Windows evidence.
- [ ] **Runtime smoke:** installed production app against real test API; common scenario, narrow/resized windows, DPI/text scaling, focus/accessibility, WebView2 dependency/bootstrap behavior and native lifecycle locks. Runtime tokens remain ephemeral after reload/restart.
- [ ] **Offline storage:** app-data `offline.sqlite` with encrypted envelope and WAL consistency, narrow IPC access, multi-instance claims, abrupt process termination/restart, disk-full/read-only/permission failures, account/origin/profile isolation, expiry/revocation and backup/restore. Uninstall/upgrade must warn/preserve unsynced evidence according to a documented policy.
- [ ] **Printing:** actual WebView2/system dialog, cancel/reprint, selected receipt printer and driver/paper widths. Test physical scanner input and no duplicate checkout on repeated input; document unavailable hardware functions.
- [ ] **Protocol handler:** installed `inventory:` registration, cold and warm launches/single-instance forwarding, approved HTTPS fallback, malformed/untrusted/expired/replayed links, proper uninstall cleanup and coexistence of Remote/Local Network editions. A scheme collision must not open the wrong profile/account.
- [ ] **Remote media/CSP:** inspect merged configuration in shipped artifact. Base Tauri config is self/data-only; profile packaging currently broadens images to `https:`. Replace broad access with an approved host policy before release and test allowed/blocked hosts, WSS/API allowlists and invalid TLS certificates.
- [ ] **Updates:** define signed manual-installer or verified updater policy; no updater is assumed installed. Test old→new installation with pending vault records, compatible schema changes, crash recovery and rollback limitations. Never force restart during an unresolved sale or silently downgrade a newer vault schema.
- [ ] **Real hardware:** clean physical Windows system with production installer, WebView2, target printer/scanner, offline networking, sleep/resume and standard-user storage permissions. Test local-network deployment on multiple devices against the same authorized backend if shipped; the client installer does not embed PostgreSQL/API.

## macOS desktop — launch-gated

- [ ] **Build/installer:** native `.app` and distribution DMG/package for each advertised Intel/Apple Silicon target, Developer ID signing, hardened runtime/entitlements, notarization and stapling; verify Gatekeeper on a clean machine. Earlier ARM64 `.app` success does not qualify DMG, Intel or notarization.
- [ ] **Runtime smoke:** installed app with WKWebView and real test API; common scenario, resizing/fullscreen, keyboard navigation, accessibility/text scaling, window/background locks and ephemeral credentials across restart.
- [ ] **Offline storage:** app-data SQLite WAL/encrypted vault under actual macOS permissions; interruption, restart, multiple windows/process claims, disk pressure, lease/revocation, backup/restore and origin/account/profile isolation. Validate upgrade and uninstall handling of unsynced records.
- [ ] **Printing:** native print dialog and actual supported receipt printer/paper settings, cancellation/reprint, physical scanner, error recovery without replaying payment. Verify Save-as-PDF separately if advertised.
- [ ] **Protocol handler:** Launch Services `inventory:` registration on installed signed app, cold/warm/single-instance delivery, approved HTTPS links/fallback and invalid/expired/replayed links. Verify Remote/Local Network edition coexistence and no secrets in OS/application logs.
- [ ] **Remote media/CSP:** same merged-config trusted-host gate as Windows; WKWebView remote-image/error behavior, HTTPS/WSS origins and no trust bypass for invalid certificates.
- [ ] **Updates:** qualify signed installer replacement or a separately implemented verified updater, preserving bundle identity/app-data/vaults; interrupted install, pending checkout, forward migration and safe rollback. No unsupported automatic-update claim.
- [ ] **Real hardware:** physical Mac for each supported architecture, Gatekeeper/quarantine, Keychain/signing behavior where applicable, sleep/wake and actual scanner/printer. Simulator/browser checks cannot replace installed WKWebView/hardware checks.

## Android — parity required, qualification tracked separately

- [ ] **Build/install:** `npm run build:mobile` is only JS export. Build a signed native APK/AAB with approved toolchain and declared Android/API/device matrix; test fresh install/upgrade and secure backup exclusions. Track this separately from first-launch gates.
- [ ] **Runtime smoke:** native equivalents of the common scenario, role/scope parity, safe areas, back navigation, keyboard avoidance, text scaling, TalkBack and permission denial. Expo Go alone is insufficient for release-native qualification.
- [ ] **Offline storage:** actual Expo SQLite WAL/atomic writes, encrypted vault, SecureStore auth namespace/exclusions, tamper/expiry/revocation, force-stop/restart, low-storage, background key erasure and restore isolation.
- [ ] **Printing:** Expo Print native flow, cancel/retry and supported physical printer; no inference of thermal/Bluetooth/USB capability from a successful JS export.
- [ ] **Links:** installed custom scheme and verified Android App Links using configured `EXPO_PUBLIC_APP_ORIGIN` and hosted association files; cold/warm starts, invalid links and account switching; no secrets in intent logs.
- [ ] **Remote media:** native Image has no DOM CSP. Enforce equivalent approved HTTPS source/content constraints, test network-security policy and failure fallback; Expo web requires its own browser CSP assessment.
- [ ] **Updates:** signed app upgrade and any explicitly configured OTA compatibility policy; preserve pending vault records, migrations and offline grants; no forced incompatible update during checkout.
- [ ] **Real hardware:** physical Android device, process death/sleep/network changes, SecureStore/SQLite behavior, camera scanning and advertised printer/scanner/Bluetooth permissions. Mark untested hardware unsupported.

## iOS — parity required, qualification tracked separately

- [ ] **Build/install:** JS export is not an IPA. Use full Xcode/CocoaPods, signing/provisioning and approved distribution to install a release native app; declare device/iOS versions and upgrade path.
- [ ] **Runtime smoke:** native common scenario, VoiceOver, Dynamic Type, safe areas, keyboard, rotation and foreground/background locks; verify all management workflows exist despite separate qualification status.
- [ ] **Offline storage:** Expo SQLite encrypted-vault persistence, SecureStore/device-only accessibility, backup/reinstall behavior, interrupted writes, storage pressure, grant expiry/revocation, account isolation and restart recovery on device.
- [ ] **Printing:** native Expo Print/AirPrint flow, cancel/reprint/PDF behavior where advertised and actual supported printer; no stock/payment change on a cancelled print.
- [ ] **Links:** custom scheme plus Universal Links/associated domains using configured production hostname and valid hosted association file; cold/warm install, malformed/replayed/expired links, no token disclosure.
- [ ] **Remote media:** native approved HTTPS host/content policy and ATS behavior; deny invalid TLS/mixed content, preserve placeholders. Do not copy a DOM CSP assumption into native code.
- [ ] **Updates:** signed native/TestFlight/App Store or separately approved OTA update, pending outbox retention, schema compatibility and interrupted upgrade; no automatic sensitive-data restore into another account/device identity.
- [ ] **Real hardware:** physical iPhone/iPad for SecureStore/SQLite, background eviction, camera scanner, network changes and actual printing. Xcode simulator and Metro export do not qualify these capabilities.

Cargo validation uses `cargo check --locked --manifest-path apps/desktop/src-tauri/Cargo.toml`, `cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml`, and formatting checks before profile packaging. The current context test asserts the base identifier; do not silently skip/falsify it for a generated profile. Add profile-aware artifact checks during CI implementation. Cache dependencies only with lockfile/OS/architecture keys; never cache secrets or test vaults.

Build jobs produce artifacts even before all runtime gates are available; **release remains blocked** for a launch target with a failed/unrun applicable checklist. Record mobile qualification gaps separately and preserve cross-platform implementation parity. Installed update testing is required even if distribution remains manual; no automatic updater is currently assumed.
