# Design system

## Start here

- **DS-001** [review] Reuse the actual components at `/#/design-system` before writing UI. Web and Tauri use the existing shadcn-style/Radix primitives and Vaul drawers with small token-based adjustments; do not install another component library. Native uses React Native equivalents, never DOM wrappers. A feature owns its state/permissions; primitives own presentation and accessibility.
- **DS-002** [review] Responsibility: Primitive controls; Web (relative to `apps/web/src`): `components/ui/`; Native (relative to `apps/mobile/src`): `ui/Controls.tsx`, `ui/Themed.tsx`, `ui/SelectChoice.tsx`
- **DS-003** [review] Responsibility: Reusable application patterns; Web (relative to `apps/web/src`): `components/common/`; Native (relative to `apps/mobile/src`): `ui/`
- **DS-004** [review] Responsibility: Shell/navigation; Web (relative to `apps/web/src`): `components/layout/` and app routing; Native (relative to `apps/mobile/src`): `shell/` and navigation registries
- **DS-005** [review] Responsibility: Business UI; Web (relative to `apps/web/src`): `features/<feature>/`; Native (relative to `apps/mobile/src`): `<feature>/`
- **DS-006** [review] Responsibility: Appearance adapter; Web (relative to `apps/web/src`): `theme/Appearance.tsx`, `theme/preferences.css`; Native (relative to `apps/mobile/src`): `theme.tsx`

## Tokens and user preferences

- **DS-007** [review] `packages/design-tokens/tokens.css` is the palette/metric source. Run `npm run build:shared` to generate native exports. Use semantic surface/text/primary/border/focus/status/navigation/table/chart tokens; use spacing, typography, radius and elevation tokens instead of feature-local values. Physical print/barcode black and white are deliberate exceptions. Layout breakpoints, aspect ratios and actual media dimensions may be explicit; do not replace them blindly.
- **DS-008** [review] `packages/contracts/src/settings.ts` owns schema/defaults and `resolveSettings`. Approved redesign migration: cosmetic fields resolve platform defaults → explicit account values → device constraints; business defaults/enforced and platform enforced cosmetics are retained in policy records but no longer applied. Currency and pagination retain existing policy precedence. Security/offline/operational policy is unchanged; no second settings store.
- **DS-009** [review] Preference: Appearance; Required behavior: Light, dark, system; system reacts to OS changes, including portals
- **DS-010** [review] Accent identities remain blue/teal/violet/rose/amber; apply to primary controls, active navigation, links, focus and charts in both themes. Surfaces stay neutral; status colors retain independent semantic tokens. Palette selection updates all mounted web/native consumers after account-save confirmation, without reloading or a second preference store.
- **DS-011** [review] Bundle Geist/GeistMono, Karla/Lora and license notices. New selections offer bundled assets; an existing system/serif/monospace/local choice remains available with its prior fallback. Never download a font at runtime.
- **DS-012** [review] Preference: Text size; Required behavior: Small/medium/large scale headings, controls, menus, tables and help; native OS scaling remains enabled
- **DS-013** [review] Preference: Radius; Required behavior: Rounded: restrained corners; circle: pill controls/avatars and larger card corners; multiline fields stay readable
- **DS-014** [review] Density compact/default/comfortable changes contextual gaps, rows and toolbar minima, independently of controlSize small/medium/large. Text and icon choices remain independent; controls grow for text and preserve coarse-web 44px/native 48px touch targets.
- **DS-015** [review] Preference: Icon size; Required behavior: Existing small/medium/large metrics; named icons, consistent stroke and accessible icon-only labels
- **DS-016** [review] Animation off/minimal/full changes feedback only; OS reduced motion always wins. Legacy disabled/reduced retains no nonessential motion until explicit new selection. Minimal uses opacity/shadow transitions; preserve static pending feedback.
- **DS-017** [review] Preference: Effects; Required behavior: Optional decorative elevations; disabling never removes focus, selection or functional feedback
- **DS-018** [review] Charts numbers/balanced/charts changes prominence, never calculations or access to exact values/records/exports. ChartPresentation provides numeric values plus a chart reveal in numbers mode; retain legacy visualization choices until explicit selection.
- **DS-019** [review] Preference: States; Required behavior: Simple/enhanced presentation, same data/error semantics; enhanced empty states have icon/title/description and only permitted relevant actions
- **DS-020** [review] Preference: Pagination; Required behavior: Existing pages/scroll behavior; no paginator for one page, keep bounded data loading and stable selection
- **DS-021** [review] Preference: Currency; Required behavior: Original amount plus a labeled equivalent in the selected display currency via useDisplayMoney; common CurrencyNotice supplies source/as-of/cache status. No rate means original currency plus unavailable/stale state. Payment review, cart totals, receipts, journal evidence and data-entry fields remain original; never relabel amounts or use estimates in commands.
- **DS-022** [review] Settings controls belong in Preferences, not repeated on every feature page. Keep user choice effective throughout mounted screens and overlays without resetting drafts. Explain enforced choices rather than offering an ineffective toggle.

## Screen contract

- **DS-023** [review] One authoritative heading/description and consistent action placement; preserve existing route shell and history-aware back action. Auth has its own layout; no business controls stacked under login.
- **DS-024** [review] One wrapping collection toolbar: search with leading icon/clear, filter badge/summary, view tabs where supported, relevant refresh and permission-gated creation/export. Debounce/cancel reads; never retry unsafe commands generically.
- **DS-025** [review] Existing Table/TableScroll: aligned headers/cells, fixed narrow selection column, select-all in header, right-aligned actions, tabular numeric values, token zebra rows. Wide tables scroll inside a named region, not the whole page.
- **DS-026** [review] Use StatusBadge with explicit semantic tone, never an unstyled `status-badge` span. Status is text plus color. Links underline on hover; icon actions use real tooltips and keyboard names.
- **DS-027** [review] Cards reflow with content-driven columns; preserve names, units and prices. Show selection only with authorized bulk actions. Selected counts appear only when relevant.
- **DS-028** [review] Keep cart below the sticky header with internal scrolling and visible checkout; present authoritative totals and unknown/failed states honestly.
- **DS-029** [review] Stores/terminals open read-only details first; scoped writers get Edit, Activate/Deactivate and confirmed Archive. Archival preserves history, is permanent and is not hard deletion; the server enforces parent/dependent-record rules.
- **DS-030** [review] Drawers use existing FormSheet/SidePanel and focus/keyboard/safe-area handling. Keep small confirmations in ConfirmDialog. Do not replace platform-accessible selection/menu behavior with hand-built clickable divs.
- **DS-031** [review] Empty search explains no matches; empty collections offer permitted creation; failures offer a real retry; offline/sync UI distinguishes local persistence from remote confirmation.
- **DS-032** [review] Support 320px through desktop widths, large text, keyboard, visible focus, meaningful labels/errors, screen readers, reduced motion and touch. No feature removal to fit a smaller viewport.

## Native component API reference

- **DS-046** [review] Native `ui/Themed.tsx` Text/TextInput resolve font, size, colors and state; `ui/Controls.tsx` provides Action/Field/Choice. `ui/IconAction.tsx` takes an accessible label and native icon name. Use `ui/StatusBadge.tsx`, `MetricCard.tsx`, `Surface.tsx`, `SearchControl.tsx`, `FilterButton.tsx` and `ViewTabs.tsx` for equivalent patterns. `ui/SidePanel.tsx` owns modal safe areas, scrolling and optional footer. Native controls support system text scaling; keep minimum touch targets even in compact mode. Local desktop font availability does not imply that font exists on a phone.
- **DS-047** [review] Browser/React Native Web tests do not qualify VoiceOver/TalkBack, native modals, keyboard avoidance or installed WebViews. Use the release checklist in [development](development.md#release-qualification).
- **DS-048** [review] Collection toolbars use `RecordCollection.toolbar` for search/filters and `.actions` for permission-aware creation commands after the view tabs (native equivalent: `ui/RecordCollection`). The navigation-control showcase demonstrates local-only search, list/grid and creation. Team contains membership and a salary-free staff directory; Salaries is separate from access management and Expenses. Customer retention lives in Business settings. Product edit drawers reuse ProductChannels for online actions and the versioned catalog command for activation; catalog inactivity also prevents POS sales and online publication.
- **DS-049** [review] POS quantity edits keep controls available during read-only repricing; checkout requires a fresh authoritative quote. Product discovery does not treat display currency as a listing filter. Parent activation never revives independently disabled SKUs; an older inactive default SKU may need activation in Variants and pricing.
- **DS-050** [review] Base desktop controls are 30/34/40px by controlSize, independently of 32/40/48px density row minima; page titles are 22px. Text scales, wrapping and touch minima may increase actual dimensions. Product cards use content-driven columns; hover actions remain reachable by focus/touch.
- **DS-051** [review] `components/common/ExportRecords.tsx` and native `ui/ExportRecords.tsx` accept required `headers`/`rows` (readonly string arrays), optional `name` and `label`; defaults are `records-shown` / “Export shown records”. Use only already-authorized visible rows; exports protect spreadsheet formula cells and preserve exact strings. RecordCollection includes a working showcase example. Exporting is not an all-pages/background report job. Drawer action groups use `drawer-actions` for two-column layout.
- **DS-052** [review] Security event lists use readable event/outcome labels and `MMM D, YYYY h:mm A` device-local time; details include weekday, seconds and zone. Drawers render labelled loaded event data, not JSON or another detail request. Actor labels use the authorized account email until personal names exist; identifiers remain secondary references.
- **DS-053** [review] Business notification drawers follow the same labelled-detail pattern using the business timezone, full event/read timestamps and secondary record references. Render the authorized loaded inbox record; preserve read/unread/dismiss commands and never invent missing actor names or transaction details.
- **DS-054** [review] Inventory is the combined product/stock workspace: Products & pricing reuses the catalog editor, variants, units, pricing and listing controls; Stock & movements reuses the ledger workflows. Show sections by their existing read permissions and retain command-level write/scope checks. `/catalog` is a hidden compatibility entry; navigation and product search use `/inventory`.
- **DS-055** [review] Product setup stays in one drawer: save Details, then Price & units, Quantity and optional Listing availability. The primary price form saves an immediate price; scheduled prices/variants/promotions remain advanced. Quantity records base-unit opening/add/remove movements at a selected warehouse root, never overwrites a balance. Each step saves independently, preserves confirmed earlier steps and enforces its original permissions.
- **DS-056** [review] POS uses scoped available stock to label tracked products with zero/negative stock “Sold” and disable card/detail/search additions; untracked or unknown availability is not sold out. Background catalog/pricing refreshes keep loaded content visible. A confirmed save followed by a failed refresh must say it was saved and offer a read-only reload, never imply that the mutation needs repeating.
- **DS-057** [review] Drawer widths are view-local, not account preferences. Shared `DrawerContent` uses `DrawerResizeHandle` (content ref + onResize callback) for edge dragging, 16px arrow-key steps, Home/End bounds and double-click reset; width stays within 320px and viewport minus 32px. Phone drawers fill the viewport, with no splitter. Native `SidePanel` uses `PanelResizeHandle` (width, maximum, onChange) for tablet edge dragging and screen-reader increment/decrement; small screens and menus retain their responsive layouts. These handles only change presentation, never form drafts or save/close behavior. The web NavigationControlsDemo and native showcase demonstrate the actual drawers; native gestures still require device qualification.
- **DS-058** [review] Product details: failed saves keep the draft and show a dismissible error toast (native: pinned panel notice); field errors stay beside accessible controls and reveal their section. `FormSection.open/onOpenChange` controls native sections to reveal validation errors; the native showcase demonstrates it. SKU checks debounce 350 ms and cancel stale reads; unavailable checks never claim uniqueness. The business-scoped server constraint remains authoritative, including concurrent saves.
- **DS-059** [review] SKU feedback uses an in-input check/X with accessible tooltips; the duplicate message has a hover/focus/tap product preview, limited by backend product-read permission. Native `Field.trailing` and `errorAccessory` keep equivalent affordances within the control and beside its error (showcase examples included).
- **DS-060** [review] Overview Sales trend has no collapsible daily-figures footer. The selected overview period controls its server snapshot, dates, totals and points; exact values remain available through the accessible web table/native bar labels.
- **DS-061** [review] Warehouse & storage (`/storage`) opens the searchable Locations list first, with Browse hierarchy as the secondary view under one warehouse selector on web/desktop and native mobile. Search, view controls, export and commands share the collection toolbar. Warehouse balances open on demand in a drawer; hierarchy stock uses a numeric table (labelled native cards). Location details and labels open read-only, with an authorized Edit location tab; creation and within-warehouse movement retain existing permissions and ledger commands. `/warehouse-view` remains a hidden compatibility route to this workspace. Facility administration and Stock counts & scanning remain separate workflows. Switching warehouse resets location navigation and pagination; switching tabs reloads the visible data.
- **DS-062** [review] Storage workspace tabs reuse the label-only Radix `view-tabs` treatment (native Settings tab treatment). The shell owns the page title; do not add a visible “Storage view” legend or duplicate introductory header.

## Rich descriptions and storage workspace

- **DS-063** [review] Product and online-description forms use `RichTextEditor` (web `components/common/`, native `ui/`) with controlled `value`/`onChange`; web also requires `id`/`label`, native requires `label`. Optional disabled/error associations preserve form validation. Use `RichDescription` with `value` for displays, never raw HTML. The showcase demonstrates both. Quill supports bold, italic, underline, lists and safe links; assets are local and generated for mobile by `build:shared`. Native uses an isolated WebView, Expo web an iframe; native font availability and keyboard/device behavior require qualification. Existing plain descriptions remain unchanged; the 2,000-character limit includes rich markup.
- **DS-064** [review] Storage uses one top row: Locations/Hierarchy tabs → Export locations/Create storage location/Move stock → warehouse selector. Actions retain their permissions and selected warehouse in either tab. Export covers loaded locations only. `RecordCollection.showExport` defaults to true; set false only when a parent supplies export (see showcase).

## Locked redesign direction and migration boundary

- **DS-065** [review] Use a light-default neutral enterprise foundation, restrained statuses and borders, account-accent primary actions and navigation, accent links/focus/charts and neutral content surfaces. Use canonical tokens, never a second page palette.
- **DS-066** [review] Exactly five target axes: theme light/dark/system, density compact/default/comfortable, control size small/medium/large, animation off/minimal/full, charts numbers/balanced/charts. Keep accent, radius, font, text size, icon size, pagination, effects, states, currency and other existing choices without reinterpreting their saved values. No new border or typography setting; sidebar collapse remains per-device UI state.
- **DS-067** [review] Apply defaults only to missing raw fields: light theme, compact desktop/default native or coarse-pointer density, medium controls, minimal motion, balanced charts, Geist. Preserve explicit legacy choices; no default materialization on read. Account writes remain version checked and single attempt.
- **DS-068** [review] Approved cosmetic migration is read-time and non-destructive: preserve stored policy JSON and disclose retired cosmetic enforcement in settings. Account appearance is stable across business switches; enforced currency/pagination and security/operational constraints remain authoritative.
- **DS-069** [review] Geist assets are pinned by SHA and checksum in `packages/design-tokens/fonts/geist-source.json`; font license is distributed through the generated token package and both showcases. Deploy compatible settings server and clients together: older strict schemas may reject new preference keys.

- **DS-070** [enforced: npm run audit:ui] Design check rejects new static literal/control violations against the reviewed baseline and reports removed ones; it is not a visual/accessibility proof. Shared table/selection rules live in `theme/shared-collections.css`, shared control/command/collection rules in `theme/shared-controls.css`; feature layout remains in its owning sheet.
- **DS-071** [review] Local showcases expose density, control size, animation and chart choices without saving account records. Common chart presentation maps `components/common/ChartPresentation.tsx` to native `ui/ChartPresentation.tsx`; both accept label, chart children and exact values. Existing SearchControl/FilterButton/ViewTabs/RecordCollection/QuantityControl/MetricCard/AsyncState/WarehouseSelect/ExportRecords map to same-named native ui components; FormSheet maps to SidePanel, ConfirmDialog to ConfirmAction, FormField to Field, DataValue to DataRow, and Table/TableScroll to RecordTable. Native APIs adapt platform semantics, never import DOM primitives.
- **DS-072** [review] Verify default/corner combinations in both themes: all densities × control sizes, small/large text, both radius styles, all accents, reduced motion, retained fonts and account/business switching. Evidence in `.ai/reports/redesign/phase-3-validation` distinguishes CSS probes, actual control interactions and platform limitations; native-web tests do not qualify installed devices.

- **DS-073** [review] Shell collapse/width are optional device-local layout (`inventory.sidebar.layout`), never account preferences. Sidebar identity/profile stay pinned while destinations scroll; single-destination groups are direct links. Native More preserves the same authorized destinations. Preferences group Basic (theme/density/control size), Advanced styling/performance, and regional/list behavior; display device constraints without overwriting saved choices. Setup progress uses only server checklist flags.

- **DS-074** [review] POS keeps the characterized shared transaction model. Held carts use existing accessible collapsibles without unmounting drafts; narrow web layouts expose a cart jump and native retains its cart dock. Desktop cart constraints and the two-column breakpoint must agree (1100px); tablet carts remain in normal flow. Receipt display/print preserve exact receiptText output; physical black/white print styles are intentional exceptions to screen tokens and never confirm printer delivery.

- **DS-075** [review] Inventory product detail uses labelled metadata and compact status groups; price history and movement history reuse existing tables (native RecordTable). Movement details open from the loaded record in FormSheet/SidePanel, retain all exact deltas/reasons/source references and identify actor IDs as references, never invented names. Existing product setup saves, archive state, stock commands and permission guards remain authoritative.

- **DS-076** [review] Purchasing keeps supplier/order creation beside its collection and supplier editing beside the selected supplier. Selected order and invoice details use existing drawers/native panels; exact line, receipt, return and settlement evidence uses tables with explicit units and reference labels. Receiving, returns and cash settlement remain separate guarded commands; presentation never completes or pays an order.

- **DS-077** [review] Warehouse scanning separates product, location and count-review context without posting on scan. Count evidence uses exact server quantities, explicit hidden/not-counted values and a recount warning for stale lines; never infer expected stock during blind capture. Storage metadata uses RecordDetails and warehouse totals use Table/RecordTable with explicit empty states. Retain scoped movement/reservation commands and label root versus direct-location balances.

- **DS-078** [review] Transfer lists keep draft creation with collection controls; detail drawers/native panels distinguish route metadata, lines, receipts and event history. Show selected-unit quantities separately from approved/settled base units and good/damaged/shortage receipts. Use loaded authorized warehouse names, label unresolved identifiers as references and never infer receipt time or actor names. Existing state-specific confirmation forms own all transitions.

- **DS-079** [review] Cash shifts use a compact reconciliation table and loaded-record detail drawer/native panel; expected/counted/discrepancy stay exact currency minor units, with uncounted values explicit. Shift commands remain scoped to the selected record; pass the safe workflow error into CommandForm.error so failed closes remain announced inside the active drawer. Sales retain exact receiptText/print adapters; separate recorded return/refund evidence from authorized correction commands and never infer refund success or printer delivery. Cash shifts use server-side composable filters; the current user’s open-shift summary is independent of history filters. Warehouse context opens the existing selector directly. Product cards stretch their detail action while keeping selection/menu controls separate.

- **DS-080** [review] Customer drawers separate profile and credit policy from recorded receivables, cash payments, credits, refunds and customer prices. Use existing details and table primitives with exact units, business-timezone timestamps, explicit missing-history states and secondary references. Editing, archival, credit and payment forms retain their scoped permissions and original commands; retention remains in Business settings.

- **DS-081** [review] Payables compares server balances in separate currency rows and exact minor units; invoice drawers separate supplier context, balances, uncredited returns and recorded settlement history. Use readable event labels and business-timezone dates, keeping missing references explicit. Warehouse/supplier filters and guarded cash/credit commands retain their existing query, scope and retry identities.

- **DS-082** [review] Accounting separates all-date, per-currency trial balances from paged periods, journals and unposted sources. Journal drawers retain exact debit/credit lines, posting dates and source/reversal references; show recorded timestamps in business timezone without changing UTC posting/period rules. Pending counts never imply reconciliation. Original permission, confirmation and idempotent command paths remain authoritative.

- **DS-083** [review] Reports present the loaded response's category, UTC date range, as-of timestamp, exact units and current-page scope together. Keep current inventory/outstanding balances distinct from period flows; preserve server notes and separate currencies. Exports contain loaded rows with unchanged columns, never a silently expanded dataset. Browser print uses legible paper tables and context without navigation, filters or duplicate metric cards; native retains its export adapter. Do not fabricate charts from unrelated measures or change legacy UTC aggregation during visual work.

- **DS-084** [review] Business trading presents relationship references, shared order terms and on-demand event history separately. Preserve exact agreed quantities/units/prices; identify unknown counterparties by business reference, never invent names. History timestamps use the business timezone; coordination states do not post stock or money. Existing bilateral consent, versioned commands and retry identities remain authoritative; filters cannot exceed the API's offset-only support.

- **DS-085** [review] Integrations distinguish server-reported Built-in only, Not configured and Enabled states; none is a live connection test. Retain operator-owned configuration guidance and permission-filtered navigation labels. Show navigation-only assistant controls solely for explicitly enabled AI; never add credential inputs, activation shortcuts or inferred provider readiness during presentation work.

- **DS-086** [review] Tabs must reference mounted, labelled panels through loading/error states. Snapshot fixtures use a fixed clock, locale, bundled fonts and bounded mock data; screenshot stability is separate from design approval and device accessibility. Native panels preserve safe-area/keyboard handling and real Text children; DOM-only adapters are not native rendering evidence.

- **DS-087** [review] Product pricing separates Variants, Units and packaging, Price history, Scheduled prices/server quote and Promotions. Selected-variant context limits unit/quote/history choices; measurement filters new base units, existing bases stay immutable, defaults offer only configured conversions. Attributes describe variants, never calculate quantities. Draft/edit promotions are unsupported; publish and withdrawal remain separate contextual operations. Product image editors preview, replace, remove and order up to five validated HTTPS URLs; failures preserve drafts. Self-hosted upload accepts PNG/JPEG/WebP up to 512 KB, shows pending/failure, retains drafts and adds the confirmed HTTPS URL. Uploads are public photo assets, not private documents.

- **DS-088** [review] Bulk import uses file → original spreadsheet preview → explicit mapping/template → validation/review → confirmation → results on web/Tauri/native. Preview the first 20 source rows, validate all 100 maximum, show original row numbers and field errors, and allow error export. CSV/XLSX are bounded to 1 MiB/32 columns; XLSX first-sheet values only. Missing template columns block validation. Unsupported category/unit/variant/tax/image mappings are explained, never inferred. Uncertain submissions freeze the payload and offer only a same-key retry; no auto-import or auto-retry.

- **DS-089** [review] Sales receipt collections use `RecordCollection.allowGrid=false`; product browsing retains view choice. Category/customer creation and shown-record exports belong in `ScreenHeader.actions` (also native). Transfers and supplier balances show store plus warehouse context in the header: store narrows authorized warehouses, totals remain server-calculated for the explicitly selected warehouse across all pages, never summed from loaded invoices. Clear optional customer filters without clearing required store scope.

- **DS-090** [review] Team header actions are Export shown records and Add member (existing invitation/account assignment semantics). Business/company, stores & terminals, security and business audit keep their `/settings/*` URLs but are standalone sidebar destinations, not personal tabs. Salary forms/profiles label compensation separately; `CommandField.section` adds presentation headings without changing validation or payloads. `RecordCollection.emptyState` accepts an existing loading/error/contextual empty component; it must not show “no matches” while a read is pending or failed.

- **DS-091** [review] MoneyValue/useDisplayMoney accept original amounts and currency only; CurrencyNotice identifies rate source/as-of/expiry. RecordCollection.exportDetail retains original CSV evidence when its visible detail includes an estimate. Display changes must not trigger price writes, reprice carts, change query denomination or alter selection/drafts. Showcase currency choices use original sample values; absent rates demonstrate safe fallback, not fake conversions.
