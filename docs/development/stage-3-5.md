# Stage 3.5 — design system and AI foundation

## Original implementation and plan

Inspection found npm workspaces with one lockfile; React 19/Vite 8/Tailwind 4 web; existing shadcn-style Button, scoped Radix dialogs/menus, native DOM form controls, Zod contracts, and a lazy hash-router showcase. Tauri 2 embeds the web frontend. Expo 58/React Native 0.88 has separate native UI and real platform adapters. NestJS/PostgreSQL remains independently deployable. Stage 3 already implemented inventory, purchasing/returns, transfers/counts, POS/cash/credit/returns, customer AR and supplier AP; these workflows were reused.

The latest workspace repair already provided permission-filtered navigation and automatic business selection. Remaining UI gaps were a light-only web palette, separate small native palette, unthemed native Text usage, limited showcase/documentation, repeated pagination and inconsistent shared form styling. No AI integration or provider existed. The planned change was shared tokens and theme adapters, incremental common-component improvements, an expanded actual-component showcase, and a disabled internal AI module with explicit trust boundaries. No new business tables or replacement feature framework was needed.

## Design and component choices

Both palettes cover background/foreground, card/elevated surfaces, primary/secondary/accent, muted text, borders/input/focus, destructive/error, success/warning/info, sidebar, selection and readable disabled states. Error uses the destructive semantic foreground. Metrics cover 4px spacing, 14/16/20/28 typography, weights/line height, widths/breakpoints, radius/border, elevation, icon/target sizes and motion timing. Tailwind's existing 640/1024 breakpoints match the documented design breakpoints; media breakpoints are build-time layout choices, not user theme settings. Native controls use 48-unit actions/inputs; desktop/browser defaults are 44px. No charts are present, so no chart library or speculative visualization palette was added.

Web keeps existing shadcn/Radix primitives, native HTML controls and system fonts. The sole new external runtime dependency is `lucide-react@1.60.0`, used through named imports for accessible icon-button/loading examples. The new `@inventory/design-tokens` workspace is pure data/build output with no runtime dependency. Native Reusables was evaluated, but adding its styling framework solely for visual parity would duplicate the current native primitive layer. Expo keeps improved native components. No icon library was added to native, no second frontend framework, Storybook, form framework, AI SDK or visualization dependency was installed.

See [the component APIs](common-components.md) for paths, props/types, defaults, variants, keyboard behavior, examples, limitations and platform support of every common component. The showcase renders that documentation directly. New common components must update examples, docs and relevant tests together. Existing feature folder names are preserved.

## AI scope and safety

See [AI foundation boundaries](../ai/provider-foundation.md). AI is disabled by default; no provider is installed. The only internal scaffold operation is versioned navigation help with strict input/output schemas and static section labels filtered by existing backend permissions. There are no business records, secrets, SQL handles, action tools or tenant IDs in provider requests. Access is checked before context construction and again after inference. Unknown/uninstalled provider configuration fails closed. Timeouts abort, concurrency is bounded and requests are not automatically retried. Logs contain allowlisted metrics, never content. No working AI assistant, production provider behavior or autonomous feature is claimed.

## Limits and manual qualification

- Appearance is view-local, starts at system and resets on reload/restart. Command 25A should provide persisted personal preferences through the existing adapters; no second settings system is introduced here.
- Web and Tauri share DOM UI; native mobile uses separate controls with equivalent semantics. Theme changes preserve mounted drafts. Native device safe areas, software keyboards, VoiceOver/TalkBack modal focus, gestures and printer/hardware behavior still need actual device qualification.
- Physical barcode/print artwork intentionally retains black/white contrast independently of theme.
- Existing Stage 3 screens remain functional foundation screens. This is incremental standardization, not a replacement of every operational screen with a new table/grid application.
- No full accessibility certification, Windows host build, Android/iOS signed device build or production AI readiness is implied by JavaScript exports/tests.
- Stage 4, Command 25A and Command 34 have not begun. Stop for review after this stage.
