# Validation and acceptance

## Available today

[README commands](../../README.md) are the canonical command reference. `validate` runs formatting, documentation/source review thresholds, ESLint/import boundaries, strict type checks including test/tooling code, tooling regression tests, Vitest, and shared/API/web builds. Set a valid `VITE_API_BASE_URL` or copy the example environment before validation. `build:mobile` separately exports Android/iOS JS bundles and Expo web. `build:desktop` requires native toolchains. Do not interpret JS export as a native release build.

`npm test` first runs Node tooling regression tests (forbidden import probes and JavaScript lint enforcement), then Vitest. Vitest includes `.test.ts` and `.test.tsx`, resolves the web `@/` alias, and covers server-rendered UI state semantics, environment rejection/redaction, typed transport responses, versioned HTTP health, CORS, headers, error envelopes and request validation. Nest test compilation uses TypeScript's legacy decorators/metadata through a small pre-transform; it does not weaken application types. `test:integration` requires `TEST_DATABASE_URL` and fails explicitly without it; it queries real PostgreSQL and closes the pool. Entry smoke tests now cover real browser mounting in jsdom, Expo registration with a browser-native renderer, the real Nest application factory, and shared compiled exports. Native desktop tests generate the real Tauri context. Workspace scripts select only their own tests; see [workspace commands](workspace-boundaries.md). The Playwright design-system suite checks light/dark appearance at 320px and 1440px, system changes, axe accessibility, keyboard/modal/menu behavior and layout. Business workflows have separate real-API browser checks. See [design system checks](design-system.md) and [Stage 3.5 results](stage-3-5.md).

The foundation checker validates local Markdown file targets, required documents and source-size review warnings. It does not validate heading anchors or external links. Generated native/build directories are excluded. Dependency-cruiser enforces cycles, resolution and app/shared/runtime boundaries; strict shared-package configs omit DOM/Node globals. Review runtime behavior in addition to these structural checks.

Keep tests adjacent to implementations (`.test.ts`/`.test.tsx`); PostgreSQL tests use `.integration.test.ts`. Native tests need the corresponding OS/device. A future CI service should run the same commands but is not introduced under this task's scope. Record current check evidence in the [foundation audit](foundation-audit.md); the [Command 1 record](validation-status.md) is historical. never use success-only stubs for unavailable runners.

Use real PostgreSQL for SQL transaction, isolation and RLS checks; an in-memory mock cannot prove them. Contract tests run against every supported persistence adapter. Exercise persisted state across restarts, not only a network toggle. Never silently discard unsent work during test cleanup of recovery scenarios.

Feature acceptance records behavior, tenant permissions, confirmed/provisional semantics, applicable platform evidence and missing foundation blockers. Run focused checks first, then required package/production checks; repeat only when changes or failures justify it. Report skipped checks and why.

### Retaining an isolated authentication test database

Set `TEST_RETAIN_DATABASES=true` for suites using `authFixture` when cleanup has not been authorized or a failed database needs inspection. The fixture still creates a random `auth_test_*` database and runs all up migrations and test assertions. It closes connections but skips down-migration and database-drop checks. This mode does **not** verify rollback migrations; normal mode retains the existing cleanup behavior. Record retained names in the QA report and remove them only with the required approval. Never point a test at production.
