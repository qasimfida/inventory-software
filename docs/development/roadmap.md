# Incremental implementation roadmap

This is a proposed sequence, not authorization to implement. The foundation task ends here. Each later slice needs a feature-specific request and the [workflow](feature-workflow.md).

| Stage                              | Bounded outcome                                                                                                    | Exit evidence / decision gate                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 0 — current                        | Documentation and foundation checks                                                                                | Links and formatting valid; no business code                                                                                      |
| 1 — executable foundation          | npm workspaces, minimal web/API shells, domain/contracts boundaries, strict TS/ESLint, CI/test/build tooling       | Real builds and checks; no placeholder business modules; choose compatible versions/schema/test tools                             |
| 2 — platform/storage qualification | Native shell prototypes and transactional persistence adapters under explicit scope                                | Confirm mobile OS matrix, scanner/printer feasibility, SQLite/IndexedDB atomicity and upgrade/recovery; decide Tauri/React Native |
| 3 — tenant/security foundation     | Identity, memberships, scoped authorization, audit and offline authorization policy                                | Cross-tenant negative tests, credential handling and revocation behavior                                                          |
| 4 — catalog vertical slice         | Products/units/versioned pricing with contracts and applicable UI                                                  | Shared validation, tenant coverage, local reads, migration compatibility                                                          |
| 5 — offline inventory slice        | Movement ledger, balance projections, reservations and first end-to-end sync                                       | Transaction rollback/concurrency/idempotency; duplicate, crash and conflict recovery on applicable adapters                       |
| 6 — POS and finance slice          | Checkout, receipt, returns, refunds and cash/payment allocations                                                   | Rounding/tax/oversell/price policies decided; lost-response and reversal integrity; printer qualification                         |
| 7 — purchasing and trading         | Suppliers, receipts, credit, warehouse transfers and inter-business trade                                          | In-transit reconciliation, partial receipts and cross-owner authorization                                                         |
| 8 — incremental extensions         | Counts/locations, reports, notifications, configurable industries; visualization/integrations/AI only as justified | Relevant acceptance, performance and access tests; lazy loading; explicit business case                                           |

Stages may be split further. Bring a dependency forward when a requested slice needs it; do not ship offline-capable business workflows before their durable storage/sync guarantees exist. Offline design applies from the first data slice, not as a later retrofit. Every slice applies the cross-platform default and reports unavailable platforms.
