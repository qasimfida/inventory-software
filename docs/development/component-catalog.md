# Common component API catalog

This is the API reference for all exports in `apps/web/src/components/common/` and reusable native equivalents. Named imports use the file paths below; web examples use the existing `@/` alias. No barrel or new UI package is needed. `React.ComponentProps<typeof Component>` is the canonical inferred public type when a named props interface is not exported. Examples use local state (`useState`) and illustrative values, never business commands. The actual interactive examples live at `/#/design-system`.

## Shared contract

Every web component uses semantic CSS tokens, supports light/dark/system appearance, inherits text-size and density settings, and respects disabled motion/OS reduced motion. Layout wraps; overflow must be explicitly handled for data tables. React, existing UI primitives and the appearance context are the only dependencies unless noted. Props are required unless marked `?`; optional DOM props retain HTML defaults. Caller callbacks own all fetching, authorization, pending/error state and business behavior. Components do not grant permissions. No example supplies real credentials or invokes production data.

## Layout.tsx — Page, Panel, Stack, Cluster, Grid

Path: `apps/web/src/components/common/Layout.tsx`.

- `Page(props: ComponentProps<'main'>)`: one page landmark with skip link, focusable `#main`, max-width and responsive outer padding. Use once per screen; never nest Pages or override its ID without adapting the skip link.
- `Panel(props: ComponentProps<'section'>)`: passive bordered surface with token radius/padding. Supply a heading and `aria-labelledby` or `aria-label` when it should be a named region. Do not imply clickability or wrap every subsection in panels.
- `Stack`, `Cluster`, `Grid(props: ComponentProps<'div'>)`: vertical flow, wrapping action row, and one/two-column layout (two at `lg`). Use for layout only, not semantic tables/lists. Default gaps are 4, 3 and 6 spacing steps respectively.
- All accept optional `children`, `className` and corresponding HTML props. `className` merges via `cn`; no variant prop or built-in data state. No keyboard behavior beyond Page's skip link. No extra dependencies.

```tsx
import { Page, Panel, Stack, Cluster, Grid } from '@/components/common/Layout';
import { Button } from '@/components/ui/Button';
<Page>
  <Stack>
    <h1>Component preview</h1>
    <p>Local examples</p>
  </Stack>
  <Grid>
    <Panel aria-label="Summary">Summary</Panel>
    <Panel aria-label="Details">Details</Panel>
  </Grid>
  <Cluster>
    <Button onClick={() => setOpen(true)}>Open preview</Button>
  </Cluster>
</Page>;
```

## IconButton.tsx — IconButton

Required: `label: string`, `icon: LucideIcon`. Optional: all Button props except `children`, `aria-label`, `size`, `asChild`. Default `variant='outline'`, forced `size='icon'`; caller may override variant. Use for familiar compact actions with a specific name; use text buttons for ambiguous actions. The icon is hidden from assistive technology, label supplies accessible name and native title; browser title is not a custom touch tooltip. Tab/Enter/Space, busy suppression and focus ring come from Button. Fixed target expands for coarse pointers. Depends on Button and existing Lucide types.

```tsx
import { IconButton } from '@/components/common/IconButton';
import { RefreshCw } from 'lucide-react';
<IconButton label="Refresh preview" icon={RefreshCw} loading={pending} onClick={refreshPreview} />;
```

## FormField.tsx — FormField and ErrorSummary

`FormField`: required `label:string`, `children:(control)=>ReactNode`; optional `id:string` (generated by useId), `description:string`, `error:string | undefined`, `required:boolean` (unset). The render argument is `Pick<ComponentProps<'input'>, 'id' | 'aria-invalid' | 'aria-describedby' | 'required'>`; spread it on the actual Input/Select/Textarea. Use for one labelled control, not fieldsets or hidden controls. Error and hint IDs associate with the control; required marker is decorative while native `required` supplies semantics. It never validates. Labels/errors wrap and use theme colors. Depends only on React.

`ErrorSummary`: required `errors:{id:string;message:string}[]`, plus optional `ComponentProps<'div'>` including ref. Empty array renders nothing. Otherwise an alert/focusable summary lets Enter/Space focus each referenced control. Caller focuses the summary after submit, not every keystroke. Use for actionable form errors, not generic API errors. No variants or automatic timeout.

```tsx
import { FormField, ErrorSummary } from '@/components/common/FormField';
import { Input } from '@/components/ui/FormControls';
<ErrorSummary errors={error ? [{ id: 'reference', message: error }] : []} />
<FormField id="reference" label="Reference" description="Local document reference" error={error} required>
  {control => <Input {...control} value={reference} onChange={e => setReference(e.target.value)} />}
</FormField>
```

## AsyncState.tsx — LoadingState, EmptyState, ErrorState

- `LoadingState({message?:string})`, default `Loading…`: polite status, or Skeleton for enhanced settings. Use during a real pending operation, never as evidence of completion.
- `EmptyState({message:string,announce?:boolean=false})`: passive text (optional polite role=status announcement), bordered under enhanced settings. Use after a successful empty result; never conceal a failed request.
- `ErrorState({message:string,onRetry:()=>void})`: persistent alert and outlined “Try again” button. Use recoverable failures; caller decides safe retries/idempotency. No auto-dismiss, retry loop or disabled prop.

All wrap text, inherit theme/density and use existing appearance context; LoadingState additionally depends on Skeleton, ErrorState on Button. Keyboard retry is Enter/Space. No built-in offline state: compose honest local/pending text using role=status, as the showcase does.

```tsx
import { LoadingState, EmptyState, ErrorState } from '@/components/common/AsyncState';
<LoadingState message="Loading preview…" />
<EmptyState message="No example rows." />
<ErrorState message="Preview failed." onRetry={() => setState('empty')} />
```

## ConfirmDialog.tsx — ConfirmDialog

Required: `trigger:ReactElement`, `title:string`, `description:string`, `confirmLabel:string`, `onConfirm:()=>void`. No optional props or variants; uses compact destructive confirmation. Use before consequential explicit actions; not for routine informational dialogs or async-progress UI. The trigger must accept Radix forwarded props/ref (Button does). Cancel gets initial focus, Tab is trapped, Escape cancels, outside pointer dismissal is prevented, focus returns to trigger. Only confirm invokes the callback, then closes; it does not await a Promise or render command errors. Caller owns duplicate prevention and results. Responsive compact width, bounded scroll, themed overlay. Depends on existing Radix Dialog wrappers and Button.

```tsx
import { ConfirmDialog } from '@/components/common/ConfirmDialog';
<ConfirmDialog
  trigger={<Button variant="outline">Reset preview</Button>}
  title="Reset preview?"
  description="Only the local example will change."
  confirmLabel="Reset"
  onConfirm={() => setReference('')}
/>;
```

## CommandForm.tsx — CommandForm

Required `definition:CommandForm` from `@inventory/api-client` and `run:(work:()=>Promise<unknown>)=>void`. Definition has required `title:string`, `fields:CommandField[]`, `submit:(values:FormValues)=>Promise<unknown>`. Fields require `name,label:string`; optional `kind:'text'|'number'|'boolean'|'select'|'multiline'` (text rendering), `value:string|number|boolean` (empty), `required:boolean` (true), `options:{value,label:string}[]` (empty). `FormValues=Record<string,string|number|boolean>`.

Use for existing simple command definitions; not for complex dynamic forms or new validation rules. Fields are uncontrolled: changing definition values does not reset mounted fields. Number/boolean kinds coerce on submit; decimal quantities must remain text to preserve exact precision. Text maxLength=500, multiline=2500. Unique titles/names are needed for unique IDs. Uses FormField and native controls; submit is keyboard accessible. Wrapping labels and themed form surface; caller/run owns pending/error/permissions, the component has no busy prop. Dependency on API-client is a type-only definition, no transport call.

```tsx
import { CommandForm } from '@/components/common/CommandForm';
<CommandForm
  definition={{
    title: 'Preview quantity',
    fields: [{ name: 'quantity', label: 'Quantity', value: '1.250000' }],
    submit: (values) => {
      setMessage(String(values.quantity));
      return Promise.resolve();
    },
  }}
  run={(work) => {
    void work();
  }}
/>;
```

## Pagination.tsx — Pagination

Required `label:string`, `offset:number`, `hasMore:boolean`, `onChange:(offset:number)=>void`; optional `pageSize:number=25`, `busy:boolean=false`. Use alongside server-paged results, not to download or slice entire datasets. Offsets must be nonnegative and pageSize positive; no component validation or total-count inference. Previous clamps at zero; next advances pageSize. Busy disables both, first disables previous, !hasMore disables next. Named navigation and native buttons preserve keyboard interaction. Wraps on small screens; depends on Button.

```tsx
import { Pagination } from '@/components/common/Pagination';
<Pagination label="example records" offset={offset} hasMore={offset < 50} onChange={setOffset} />;
```

## DataValue.tsx — MoneyValue and BusinessDate

`MoneyValue({amount:string,currency:string})`: format an exact minor-unit integer string with the domain `formatMinorUnits`; currency determines precision. Not for floating point or major-unit text. No conversion/rounding API. Passive tabular text inherits colors/size; no forced truncation.

`BusinessDate({value:string,timeZone?:string='UTC'})`: semantic time element using contracts `businessTime`. Value is the timestamp string; explicit business time zone avoids implicit host conversion. Not for selecting dates or changing date-only semantics. Both have no keyboard actions or state; invalid values remain caller validation responsibility. Dependencies are existing portable domain/contracts functions.

```tsx
import { MoneyValue, BusinessDate } from '@/components/common/DataValue';
<MoneyValue amount="12500" currency="USD" />
<BusinessDate value="2026-10-20T12:00:00Z" timeZone="Asia/Karachi" />
```

## MetricCard.tsx — MetricCard

Required `label:string`, `value:ReactNode`, `unit:string`; optional `primary:boolean=false`. Use for exact precomputed measures with explicit units; not for calculating totals or implying partial pages are complete counts. Passive card, no interaction or loading prop; compose LoadingState separately. Values wrap with tabular figures, primary uses matching foreground/background tokens; responsive grid is caller-owned. React only.

```tsx
import { MetricCard } from '@/components/common/MetricCard';
<MetricCard label="Confirmed quantity" value="12.500000" unit="each · example only" primary />;
```

## WorkspaceControls.tsx — compatibility helpers

Keep these small existing offline/warehouse consumers working; prefer FormField and primitives in new forms. No domain rules or persistence live here. All are named exports at `apps/web/src/components/common/WorkspaceControls.tsx`.

| Export | Required props                                                                               | Optional/defaults | Use and limits                                                                                                 |
| ------ | -------------------------------------------------------------------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------- |
| Box    | children:ReactNode                                                                           | None              | Section with top divider/spacing; not an interactive card                                                      |
| Txt    | children:ReactNode                                                                           | None              | Paragraph, no tone/heading API                                                                                 |
| Act    | label:string, onPress:()=>void                                                               | disabled=false    | Button adapter; not async command handling                                                                     |
| F      | label:string, value:string, onChange:(s:string)=>void                                        | None              | Controlled text input, implicit label; not number coercion                                                     |
| Pick   | label:string, value:string, onChange:(s:string)=>void, options:{value:string;label:string}[] | None              | Native controlled select; no search or disabled-option API                                                     |
| Secret | value:string, onChange:(s:string)=>void                                                      | None              | Password input, autocomplete off, fixed offline-passphrase ID; one per mounted view, no length validation here |

Use keyboard behavior from native controls, wrapped labels and semantic primitive colors. Box/Txt depend on React only; others on Button/Input/Select. Secret's label describes policy but does not enforce it; backend/offline owners enforce limits. Never put a real secret in showcase state.

```tsx
import { Box, Txt, Act, F, Pick, Secret } from '@/components/common/WorkspaceControls';
<Box>
  <Txt>Local example</Txt>
  <F label="Reference" value={reference} onChange={setReference} />
  <Pick
    label="Location"
    value={location}
    onChange={setLocation}
    options={[{ value: 'main', label: 'Main' }]}
  />
  <Secret value={secret} onChange={setSecret} />
  <Act label="Clear example" onPress={() => setSecret('')} />
</Box>;
```

## Layout ownership and limits

`components/layout/SectionNavigation.tsx` exports `SectionNavigation`: required `items:{name:string;label:string;Icon?:LucideIcon}[]`, `current:string`, `onSelect:(name:string)=>void`; optional `label='Workspace sections'`, `sticky=false`, `rail=false`. Use for workspace sections, not ARIA tabs or authorization. Caller filters items. Active item uses aria-current, all actions use Tab/Enter/Space. Rail collapses below1024px; pointer/focus shows desktop labels, Escape hides them. Local menu state does not alter route destinations. Depends on Button/Lucide.

```tsx
<SectionNavigation
  label="Preview sections"
  current={section}
  onSelect={setSection}
  items={[
    { name: 'summary', label: 'Summary' },
    { name: 'details', label: 'Details' },
  ]}
/>
```

`components/layout/WorkspaceHeader.tsx` exports `WorkspaceHeader({onSettings:()=>void,settingsOpen:boolean})`, both required. Workspace-only header with fixed Inventory h1 and Settings/Back button, aria-pressed state. Do not insert into nested panels/showcase (would duplicate h1). Uses Button/Lucide and responsive workspace CSS; caller owns settings visibility and draft retention. Usage: `<WorkspaceHeader onSettings={() => setOpen(!open)} settingsOpen={open} />`.

Neither layout component fetches data. Feature-owned auth/catalog/cart/report components stay in their existing flat feature directories; no directory-wide migration is justified.

## Responsive interaction refinements

SectionNavigation's existing rail example demonstrates an explicit `aria-controls` relationship, Escape collapse and focus return to the visible toggle after selection. When a desktop rail shrinks to the narrow layout, focus moves from a newly hidden item to that toggle. When widening hides a focused toggle, focus returns to the current section (or the first available item if none is current). Resizing never moves focus away from an unrelated control. No destination or menu visibility permission changes. MenuContent bounds its minimum width at enlarged text; existing ReferencePanel remains the live menu example. DialogContent contains overscroll and wraps long content while retaining the original Radix focus/dismissal contract. See [responsive and accessibility audit](responsive-accessibility.md).
