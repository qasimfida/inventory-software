# Appearance and performance preference refinement — Prompt 6

## Audit and impact map

The existing account settings remain authoritative. `packages/contracts/src/settings.ts` defines the options and resolver; `packages/api-client/src/settings/` owns server persistence and versioned saves. Precedence remains defaults → platform defaults → business defaults → account values → business enforcement → platform enforcement → device reduced-motion/low-power limits. No second store, preference reset, contract, route, permission, database or business-operation changes were introduced.

| Layer            | Existing ownership                                                                                                                                | Refinement                                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Canonical tokens | `packages/design-tokens/tokens.css`, generated native exports                                                                                     | Reused; no new palette or font dependency                                                                                                                                                       |
| Web/Tauri        | `apps/web/src/theme/Appearance.tsx`, `preferences.css`, `workspace.css`                                                                           | Workspace spacing follows density; workspace header actions wrap at large text on narrow screens; preview type scales; semantic label/KPI tokens; disabled motion includes root pseudo-elements |
| Native           | `apps/mobile/src/theme.tsx`, `ui/Themed.tsx`, `ui/metrics.ts`                                                                                     | Accent also updates focus-ring token; existing label/heading/title tokens replace duplicate sizes                                                                                               |
| Feedback         | Web `components/common/AsyncState.tsx`; native `ui/AsyncState.tsx`                                                                                | Existing simple/enhanced setting reaches literal loading/empty results; optional announcements preserve security-result semantics                                                               |
| Consumers        | Organization, catalog/pricing, inventory/POS, supplier balances, accounting, trading, integrations, security; native reports/inbox/warehouse view | Presentation wrappers only; original messages, conditions, handlers and data sources retained                                                                                                   |
| Discoverability  | Existing web and native showcases and component catalogs                                                                                          | Actual native feedback examples; typed API/defaults/usage documented                                                                                                                            |

Native metric, stock snapshot, POS heading and Settings preview sizes now use shared metrics. The native themed text wrapper already applies account text scale and derives line height; OS font scaling remains enabled. The existing cohesive web LocationEditor crossed the 200-line review threshold after adopting feedback; its rationale is registered in `scripts/source-size-exceptions.json`.

## Supported options and deliberate limits

| Preference                          | Behavior                                                                                                                                                                                                                                                    |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Light / dark / system               | Existing providers resolve appearance; system follows OS changes. Portals inherit document tokens.                                                                                                                                                          |
| Small / medium / large text         | Existing scales 0.9 / 1 / 1.2 remain unchanged. Headings retain hierarchy; controls grow rather than clipping. Coarse-pointer web inputs retain their existing 16px minimum to avoid input zoom.                                                            |
| Font                                | System is the only accepted value. No custom font family or downloadable font was added. Technical monospace and exact tabular numeric rendering remain intentional.                                                                                        |
| Accent                              | Existing default blue and teal palettes only. Primary and focus tokens change together; destructive/success/warning meanings remain distinct. Arbitrary custom colors are not supported by the contract.                                                    |
| Enabled / reduced / disabled motion | Nonessential CSS animation, transitions and smooth scrolling stop for reduced/disabled or OS reduced motion. Native disabled/reduced loading uses static feedback; native confirmation is already nonanimated. No completion depends on an animation event. |
| Compact / comfortable               | Token-based spacing adapts across shared controls, tables and screen compositions. Minimum touch targets remain intact; breakpoints, icon geometry and barcode dimensions do not shrink.                                                                    |
| Simple / enhanced states            | Shared feedback uses text or static token-based surfaces/placeholders. Existing request/error semantics and retries stay with the caller.                                                                                                                   |
| Optional effects                    | Existing web elevation tokens switch off. Native currently has no optional shadow/blur engine to disable.                                                                                                                                                   |
| Visualization detail                | Stored/resolved as before. Current lightweight hierarchy view has no enhanced renderer; this setting does not invent charts, additional metrics or a 3D engine.                                                                                             |

Browser/OS-owned select/date/calendar/validation popups and native keyboard presentation cannot be fully themed by application CSS. Black/white warehouse barcode output is intentionally fixed for scanner readability. Decorative logo/product placeholder sizes are not body typography; native themed text still scales them. Focus/disabled/status colors stay semantic. No third-party custom calendar, drawer, chart or animated page-transition system exists to migrate.

Literal asynchronous result messages now reuse common feedback where safe. Transaction progress, offline pending/conflict descriptions, explanatory paragraphs and feature-owned result lists retain their existing semantics; do not disguise errors as empty results. See [web APIs](component-catalog.md) and [native APIs](native-component-catalog.md).

## Verification

Browser CSS matrices exercise resolved attributes; the separate real-API exercise covers actual settings saves, reloads and restoration of its disposable account. These are complementary checks, not a claim that every Cartesian combination was persisted.

- Chrome: `PLAYWRIGHT_CHANNEL=chrome npm run test:web:browser` — 20 passed, including 432 resolved CSS combinations across 320/1440px, light/dark/system, all text sizes, both accents, all motion modes, both densities and effects on/off. Checks include primary text contrast ≥4.5:1, accent/focus agreement, exact numeric strings, hierarchy, touch targets, portal theme/elevation, initial dialog focus and cancellation. OS reduced motion and injected component/root pseudo-element animation suppression pass. The test now waits for the lazy showcase provider to mount before changing resolved attributes.
- Native React components: `Preferences.test.tsx` — 108 combinations plus dark-system/OS-reduction checks. These use React Native Web in jsdom to verify shared native component props/styles; they are not native-device proof. Additional web feedback tests cover simple/enhanced styles, messages, announcements and unchanged retry invocation. Existing server-rendering feedback tests were retained.
- macOS: actual Tauri WKWebView ran 144 resolved style combinations, checked scale/system font/exact values/motion/overflow, and opened/cancelled the real confirmation dialog with initial Cancel focus and disabled portal elevation. The isolated temporary host used built application assets and performed no account writes; no test hook was added to the repository.
- Android: Expo Go in the `medium_phone` emulator rendered the actual native application against the local API and existing Design Review Store. Settings were changed through native controls to dark/teal/disabled-motion/compact with small then large text, enhanced feedback/detail and effects off. Inspected Settings, product search and a local cart containing the existing DEMO-MUG product; no sale was submitted. Restart retained the saved preferences. Captured development-account preferences were restored exactly afterward; no production records or user defaults were reset.

The combination suites are intentionally bounded: they do not exhaust every possible policy, OS accessibility setting, field length and device. Real VoiceOver/TalkBack, physical scanners/printers, iOS simulator/device and Windows WebView2 remain unverified in this environment. Font-family and arbitrary-color combinations are unavailable under the current contract. These are platform/release qualification limits, not permission to substitute web components in native screens.

The disposable PostgreSQL 18/API/browser workflow run applied all 23 existing migrations and passed 20 workflow groups. It creates its own account, business and transaction fixtures, checks original workflows and policy enforcement, exercises every supported saved preference value and reload, then checks all 16 workspace sections with small/large text at 320/768/1440px (compact, teal, disabled motion, enhanced states). The existing light/dark WCAG and responsive screen checks also pass. Initial logged 401s are expected unauthenticated session probes; authenticated localhost and 127.0.0.1 login/reload/protected requests/logout passed without unexpected 401s. The intentionally denied checkout returns 409 as before.

Regression found during this run: the long “Back to workspace” action forced the large-text header past a 320px viewport. Allowing the existing header flex row to wrap fixes it without hiding content or changing navigation. The live settings test checks element bounds. Async controlled checkbox assertions wait for the saved value; the preference sweep runs after existing lazy-loading checks so visiting every section does not invalidate their premise.

The full backend integration suite was not separately rerun for this presentation-only change; the disposable PostgreSQL/browser workflow supplies real API/database coverage. Seven non-failing source-length warnings remain (six preexisting plus the documented LocationEditor threshold), along with the web entry chunk warning (521.84 kB minified / 158.93 kB gzip). Only Command Line Tools are installed on this macOS ARM64 host, so an iOS simulator build/run is unavailable. Windows execution is skipped on this host. Expo exports alone do not qualify native production packages.

`npm run validate` passed: formatting, foundation checks, dependency boundaries, all workspace type checks, 14 tooling tests, 167 tests in 83 Vitest files, and web/API production builds. Lint reports zero errors and the seven length warnings described above. `git diff --check` passed. The task diff was compared against a start-of-task snapshot because the workspace already contained earlier implementation work; contracts, settings model/storage and canonical token files are unchanged. Feature edits retain request conditions, permissions, field names, data sources and mutation handlers.

`npm run build:mobile` passed: Android and iOS Hermes bundles plus Expo web exported successfully (approximately 3.1 MB native each / 1.4 MB web). `npm run build -w @inventory/desktop -- --bundles app` passed: normal macOS ARM64 `.app` bundle, 11.57 MiB. The normal bundle was rebuilt after the isolated WebView audit, checked for absence of its temporary test hook, and launched. The temporary host was removed. This is a local app build, not signing/notarization or Windows/iOS release qualification. No dependencies were added; visualization loading boundaries remain unchanged.
