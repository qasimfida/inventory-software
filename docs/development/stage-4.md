# Stage 4 — security and reliability

## Audit and implementation plan

The existing Nest/PostgreSQL backend uses opaque hashed sessions, scrypt passwords, invitation-only onboarding, default-deny authentication, transactional business scopes, permission/location checks and operator-only platform administration. Browser cookies, mobile SecureStore and ephemeral Tauri credentials already exist. No MFA provider/enrollment/recovery design or email delivery provider exists. Preserve these boundaries and document unqualified capabilities.

Existing offline registers use encrypted IndexedDB or SQLite envelopes, compare-and-swap writes, immutable operation IDs, bounded grants, authenticated delta downloads and server transaction/savepoint/idempotency handling. Existing inventory, purchasing, checkout, payment and count tests exercise real PostgreSQL. Stage 3.5 supplies shared tokens and separate web/native UI.

Confirmed gaps and impact map:

| Area                | Planned correction and validation                                                                                                                                                                                                                                                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Password recovery   | Add operator-issued, expiring, single-use hashed recovery codes and public rate-limited completion. Reuse scrypt; atomically revoke sessions and offline grants. Add web/Tauri/native completion controls. No fake email delivery or automatic login. Real DB tests cover invalid/expired/replayed/disabled cases, rollback and competing completion. |
| API reliability     | Preserve server-generated correlation IDs in typed client errors. Add bounded retries only for safe reads, with host-provided timing; preserve single-attempt mutations. Keep timeout active through body consumption on native and web. Test retries, malformed responses and credential clearing.                                                   |
| Offline concurrency | Prevent concurrent/late uploads from downgrading confirmed outbox entries. Persist backoff before transmission and stop exhausted retries after restart. Keep unresolved payloads intact. Bind delta cursors to currency as well as existing actor/business/warehouse/access scope. Add deterministic races and real API regressions.                 |
| Security boundaries | Recheck tenant/admin/scoped authorization, public routes, input validation, logging and development-seed restrictions. Extend tests for discovered gaps rather than rewriting established services.                                                                                                                                                   |
| Cross-platform      | Run formatting, boundaries, types, unit/integration/browser workflows, migrations, API/web builds, Expo exports, macOS build and standalone API artifact. Report Windows/device/toolchain limitations separately.                                                                                                                                     |

Migration `1794200000000_security_reliability.sql` implements recovery records, revocable offline grants and currency-scoped cursors. Existing ledger and financial rules stay unchanged. No Command 25A settings, external payment provider, AI provider or later-stage features are included.

## Implemented changes and retained boundaries

- **Command 21:** `auth/password-recovery.ts`, ResetPasswordDto, the existing AuthService/controller and admin CLI implement recovery with established random tokens/digests/scrypt. Account-first locking, generic errors and existing DB-backed credential limits cover completion; no public issuance/account enumeration endpoint. Reset, account status administration and explicit development credential reset invalidate sessions/recovery codes and call sync-owned `revokeOfflineAccess`. Web/Tauri and native `PasswordRecovery` controls clear secrets and require fresh login. Existing password hashing, rotation, expiry, account status, transport binding, CSRF, scoped permissions and operator-only platform roles are retained. MFA is not supported by the current identity design and is an unresolved production risk.
- **Command 22:** `outbox-claim.ts` and SyncEngine atomically claim current eligible operations, persist attempt counts/backoff before transmission, respect restart retry exhaustion and preserve confirmed results against late negative responses. Same-ID retry, immutable payloads, local encryption, account partitioning, IndexedDB/SQLite CAS and server transaction/savepoint processing remain. `sync-cursor.ts`, SyncCatalog and SyncDownload now bind currency, so a currency change forces full replacement instead of stale prices. Revoked grants retain unsynced sales as conflicts; owner reconciliation still runs normal authorized business services.
- **Command 23:** `read-retry.ts` supplies at most three GET/HEAD attempts with 250/500ms pauses for transport failures and HTTP 502/503/504. It never retries POST/PUT/PATCH/DELETE, 401/403/404/409 or rate limits. Web/native adapters keep their 10-second abort deadline through JSON consumption; no request waits indefinitely after headers. Shared auth clients validate acknowledgements before clearing credentials and preserve validated error/correlation metadata while displaying fixed safe messages. CORS exposes request ID/Retry-After. Existing strict schemas, bounded pagination/filtering and command idempotency remain authoritative.
- **Command 24:** New real-PostgreSQL recovery and sync-security suites cover code replacement, hashing, expiry, wrong accounts, disabled accounts, races, injected rollback, CSRF, rate limits, revoked grants and currency cursors. Client tests cover immutable outbox races/partial responses, restart backoff, safe retries and malformed acknowledgements; both UI implementations and both body-deadline adapters have regressions. Mobile adapter coverage now closes/reopens an actual temporary on-disk SQLite database using Node's SQLite engine; the Expo bridge is still adapted for this host test. Existing ledger/checkout/purchasing/payment/tenant suites were reused. The real browser scenario includes actual operator issuance and recovery.
- **Command 25:** Reviewed web routes/navigation, Tauri reuse, native UI/storage separation, environment examples, production origin/TLS validation, independent backend packaging, migration ordering, safe errors and deployment prerequisites. Server-generated IDs and structured allowlisted logs remain; private-key fields/PEM blocks are additionally redacted. No passwords, cookies, tokens or recovery codes are logged. The admin CLI's deliberately captured one-time secret output must not be forwarded to logs.

No new runtime dependency remains in Stage 4. Pre-existing Stage 3/3.5 working-tree changes were preserved. No business calculations, cash-only policy, UI framework, auth provider or AI configuration was replaced.

## Deployment and recovery

Run `npm run db:migrate -w @inventory/api` before deploying the new API. Migration 19 is additive except that it clears ephemeral sync cursors; clients receive a full refreshed snapshot and retain outboxes/leases. It does not rewrite inventory, sales or balances. Recovery code records retain timestamps/digests; the existing operator prune command removes records more than seven days past expiry. Production migration reversal remains disabled.

Migration 19 was also applied to the configured existing local database (one pending migration), with no seed/reset of user accounts or transactions. The password-reset UI is under the existing sign-in page; [operator steps](../security/authentication.md#password-recovery--stage-4) document trusted issuance and manual delivery. Email/SMS verification and MFA require separately configured, reviewed infrastructure. No fake notification delivery is returned.

Older clients still use existing wire contracts; reset is an additive endpoint. Deploy updated clients to gain outbox race/deadline fixes. Offline revocation retains the documented maximum eight-hour disconnected window, not instant remote revocation. Browser storage eviction/device loss and forgotten offline-vault passphrases require operational backup/recovery planning; password reset does not decrypt an offline vault.

## Dependency and release risks

A fresh `npm audit --omit=dev --json` reported **22 affected packages: 15 high and 7 moderate**, rooted in three advisories in the Expo CLI/config/Metro dependency tree. This current audit supersedes earlier installation-time “zero vulnerabilities” output; the application is not dependency-security cleared.

- `braces@3.0.3`: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), no published patched release at verification time.
- `node-forge@1.4.0`: [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv), no published patched release at verification time.
- `uuid@7.0.3` through `xcode@3.0.1`: [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq), patched CommonJS-compatible 11.1.1 exists. A proposed override did not produce a verified installed dependency change under this workspace/toolchain and was removed; no remediation is claimed. The inspected Xcode consumer uses `v4()` without buffers, while the advisory concerns v3/v5/v6 buffer bounds; that narrows the observed call path but is not a security clearance.

`npm ls braces node-forge uuid --omit=dev` traced these packages to Expo tooling. No corresponding application/API source import was found; this is a dependency-path assessment, not proof of universal non-reachability. Keep Metro/dev tooling private and signing inputs trusted. Resolve through a compatible upstream SDK/tooling update or separately reviewed patch before qualifying mobile releases. Do not apply npm's suggested destructive Expo 44/React Native 0.72 downgrade.

Other unresolved release qualifications: privileged MFA, verified recovery delivery/identity procedures, least-privilege production DB roles/ingress/TLS/backup operations, Windows native builds, installed Android/iOS vault/SQLite/keyboard/accessibility behavior, macOS native WebView/hardware testing and release signing/notarization. The 250-item offline snapshot/1000-record retained outbox limits and bounded revocation window remain explicit operational constraints. There is no broad penetration-test or accessibility certification claim.
