| Layer                              | Existing consumers and planned presentation change                                                                                                                                                                                                                              |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Web / macOS / Windows DOM          | Existing Table, Panel, Dialog, Menu, StatusBadge, feedback, Pagination and SectionNavigation. The only date picker is the browser's native date input in reports; native clients use explicitly labelled YYYY-MM-DD UTC fields. No custom calendar, chart/tooltip engine, ARIA tabs, breadcrumb trail, drawer, toast timeout or context-menu implementation exists. Retain these semantics rather than adding speculative controls. Section navigation is navigation, not an ARIA tab widget. Reports are paged by the server (50 rows); no virtualization or full-dataset fetch is warranted. No page redesign or Prompt 4 work is included.

## Validation

### Implementation

- Web Table and TableScroll provide 40px headers / 44px rows, 36px headers / 34px rows in compact density, 12px / 10px horizontal padding, semantic header/hover/selection surfaces and right-aligned tabular numbers. Rows grow for wrapped content. Report and warehouse tables consume them; report values/units and 50-row offsets are unchanged. Warehouse row actions use small controls.
- Shared disclosure CSS preserves native details/summary state and nested forms. Date inputs retain their native calendar, locale, YYYY-MM-DD values, UTC interpretation and existing bounds. Browser-owned calendar panels are not replaced or claimed to have fully custom styling.
- Panel padding/radius, passive compact badges, feedback spacing and pagination presentation are centralized. Menu separators reuse installed Radix primitives. No alert timers or offline semantics changed.
- ConfirmDialog uses the compact 448px variant of DialogContent (default 512px), bounded to the viewport with scrolling. Initial Cancel focus, focus trapping/restoration, outside-click protection and confirm/cancel handlers are unchanged.
- Collapsed navigation labels now appear for keyboard focus as well as hover. Escape dismisses only the visual label. Route/state callbacks, permissions, lazy imports and visited-panel retention remain intact.
- Native DataRow displays exact report strings and units without truncation or numeric conversion. Controlled DisclosureTrigger standardizes existing headers in reports, settings/policies, warehouse, notifications, trading/history, integrations, password recovery, accounting and the native showcase. It retains each caller's expansion state and effects. Native confirmations use a bounded ScrollView and shared dimensions; selected navigation foregrounds use the selected palette.
- Web DataPresentationDemo and native NativeShowcase provide real examples. These are explicitly local examples, separate from production report queries.

### Limits and review

No Windows runtime is available on this macOS host; it was skipped as authorized. iOS JavaScript export is verified, but full Xcode/iOS Simulator and signed device builds are unavailable. Android testing uses Expo Go rather than a signed standalone APK. An additional Android protected-report check was interrupted after fresh login when the emulator exited and ADB reported the device offline; report rendering on Android is not claimed as verified. Earlier native component checks passed, and protected reports passed in Chrome and macOS WKWebView. Full VoiceOver/TalkBack, hardware keyboard, native calendar UI and broader OS/browser qualification remain open; DOM keyboard and axe checks are not a complete assistive-technology certification.

The existing approximately 521KB main web chunk and six source-length warnings remain. No additional library, chart engine, speculative control framework, virtualization or full-dataset fetching was introduced. Domain/status meanings, calculations, request schemas, business validation, route destinations, permissions and synchronization behavior were not edited. Existing operational histories that use lists remain lists. Unrelated prior work in the dirty workspace was preserved. Stop after complex components; no Prompt 4 work was started.
