# Routed shell and development fixtures: implementation plan

Scope: existing web, macOS/Windows Tauri DOM frontend and Expo native apps. No commit. Preserve domain workflows, transactions and server authorization.

| Layer            | Existing owner                                                  | Planned change                                                                                                                                                                                         |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Navigation       | Web hash router, local ManagementWorkflows; native local panels | Shared route/permission metadata, routed protected web shell; native stack/bottom tabs/More equivalents. Preserve feature panels and cart state between eligible routes.                               |
| Identity         | Existing opaque sessions, invitation/reset API                  | Isolated auth layouts, password reveal/confirmation, safe recovery link parsing and explicit recovery status. No pretend admin notification/email.                                                     |
| Business context | OrganizationModel + settings model                              | Keep selected authorized membership in memory, switch/create only in Business settings or onboarding. Clear on account/role changes.                                                                   |
| Common UI        | Existing Radix DOM and native themed primitives                 | Sticky header, scrollable bounded sidebar/pinned profile, accessible search/menu, switches, settings navigation, token-only styles.                                                                    |
| Transport        | Injected AuthTransport                                          | Opt-in development-only mock adapter and deterministic shared fixtures; no network fallback or production activation. Existing runtime response schemas still apply.                                   |
| Deep links       | No current native link integration                              | Allowlisted recovery/invitation targets, custom scheme, configurable verified HTTPS hosts, mobile linking and Tauri single-instance/deep-link adapters. No secret logging or persistent token storage. |
| Offline          | Existing bounded encrypted vault/outbox                         | Post-login setup under Device & Offline, separate bounded unlock route for prepared devices; never present mock/offline data as server-confirmed.                                                      |
| Verification     | Vitest, Playwright, Expo, Tauri                                 | Route guards, shell focus/scroll/menus, mock schema coverage and isolation, scenario/role screenshots, available native runs/builds.                                                                   |

Production hostname inspection found only local origins and `.invalid` placeholders. Real domain/association files require deployment input; custom-scheme implementation can proceed. Native Windows/iOS execution depends on available host tools. Missing real recovery-delivery provider remains a documented blocker.
