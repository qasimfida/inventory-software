# Inventory interaction and visual refinement — 2026-10-21

## Delivered

The inventory workspace now has four clickable, warehouse-scoped stock metrics, related product views at `/inventory?stock=all|in-stock|low-stock|out-of-stock`, a readable stock table with semantic badges on web/Tauri, and native cards/badges on mobile. The aggregate is a new read-only, permission-scoped API query; it includes active tracked SKUs with no balance and uses one statement for counts and paginated rows.

Header controls now use an expanding search, theme toggle, unread notification badge, connectivity icon/dot and a profile popup. Profile and preferences are reachable from the top and bottom navigation; the bottom chevron opens preferences directly. The offline switch opens the existing prepared-register unlock flow without discarding the online cart or bypassing grant checks. Password reveal is inside the field. Connection setup is removed from authentication screens and remains in device settings.

Shared search, pagination, refresh/back icons and quantity controls are reused across inventory, catalog, purchasing, transfers, storage, customers and POS where the existing data contracts permit them. Search requests are debounced, superseded requests are aborted, and stale results are ignored. POS quotes refresh automatically after cart edits; Checkout opens the existing explicit payment confirmation. No automatic financial posting was introduced.

See [implementation and impact map](../../development/inventory-ui-refinement.md) and [common-component usage](../../development/common-components.md). Interactive local examples are on `/design-system`; native equivalents are in NativeShowcase. No library was installed.

## Data and behavior review

- Total products means active inventory-tracked **SKUs**, not distinct product families. Card counts cover the selected authorized warehouse; result totals additionally apply status and search.
- Available stock is on hand minus reserved minus damaged. In-transit is excluded. Out of stock is available ≤ 0. Low stock is positive availability at or below the existing business threshold; in stock is above it.
- The existing default threshold is **0**. Its low-stock card therefore correctly reads zero until the existing industry setting specifies a positive threshold. No default or saved preference was reset.
- No fake percentages, sales-by-brand chart, product photos or historical inventory trend was added. Those need authoritative data not provided by the current overview contract.
- No inventory/financial mutation, database schema, authorization rule, settings storage, payment provider or native device integration was changed. The new overview route is additive and read-only. Quote scheduling invokes the existing server quote operation; final posting still uses the original stable command IDs and confirmation flow.
- Cancellation is a portable structural interface in shared code; browser/native controllers remain in their hosts. Generic transports retain single-attempt mutations. Native UI imports no DOM/shadcn components.
- Existing unrelated uncommitted work was preserved. Isolated test databases were retained; see [retained databases](../retained-test-databases.json). Rollback migration execution was not part of this run.

## Remaining limits

Windows native compilation/runtime was not tested because this host has no Windows/MSVC/WebView2 environment. Native iOS build/simulator testing requires full Xcode/CocoaPods and was not performed; iOS JavaScript export alone is not device qualification. macOS printing, scanning, filesystem, deep links and offline restart/recovery were not requalified by these UI changes.

Cursor-only history views cannot expose a truthful final page count; they retain bounded history navigation. Some older feature-local filters retain their existing field presentation while the shared expanding search is the migration target. Notification counts cover the latest authorized page (`+` indicates more pages), not an invented global total. Connectivity reflects the most recent server check, not a continuous availability guarantee.

Web icon hints use accessible names and native browser title tooltips; native controls expose accessibility hints and long-press labels. Full native screen-reader/hardware keyboard qualification and native font/density preference permutations remain manual follow-up. The existing web preference matrix and portal accessibility checks passed in the 24-test browser suite. Existing reduced-motion and appearance settings remain authoritative; light/dark and responsive contexts were directly exercised above.
