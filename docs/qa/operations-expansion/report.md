## Explicit limitations and follow-up

1. **Offline is bounded cash checkout.** Credit, purchasing, staff costs, payments and arbitrary stock adjustments still require an online server. Full offline feature parity needs additional grant scopes, durable command contracts and conflict/reconciliation rules; this change does not pretend to queue unsupported financial operations.
2. **Desktop profiles are build options, not a hosted signed download service.** Supply verified remote/LAN HTTPS origins, provision the shared API/PostgreSQL server, sign/notarize installers and publish the two artifacts. LAN-to-cloud database replication is not implemented. Windows runtime/build verification was unavailable; iOS native/device verification was unavailable without full Xcode/provisioning. JavaScript export alone is not platform qualification.
3. **Salary/expense tracking is an operational subledger.** No statutory payroll, taxes, payslips, bank payout, automatic till withdrawal or general-ledger posting. Staff identity does not itself grant app access.
4. **Bulk import creates new SKUs and opening inventory.** It does not overwrite existing quantities, import purchase documents, evaluate formulas or accept legacy `.xls`. Downloaded CSV templates can be opened in Excel. Use normal receiving/adjustment workflows for existing stock.
5. **Server recovery is operator-only.** No tenant endpoint downloads the whole database. Managed scheduling, offsite encryption, retention, point-in-time recovery and production cutover need deployment setup. Native document/share dialogs and encrypted-vault restore still need broader device/provider qualification.
6. Existing retained-screen drawers can remain open when changing the URL programmatically; normal drawer dismissal was used before navigating in the functional walkthrough. A general route/portal lifecycle change was kept outside this work to avoid resetting unsaved forms.
7. `npm audit` reports 15 high findings through the existing Expo/Metro dependency chain (`braces` 3.0.3 and `node-forge` 1.4.0, both unchanged from the baseline lockfile). The suggested forced changes downgrade major platform dependencies; no unsafe force-fix was applied. The new spreadsheet parser packages are not among those findings.
8. Full preference permutations, physical barcode/printer hardware, every native file provider, production load, and every possible transaction sequence were not manually retested. Automated coverage and actual runtime evidence above define the verified scope.
