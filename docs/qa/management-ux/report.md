# Management and product workflow refinement

## Impact map

- Existing catalog schemas/commands → grouped product forms and pricing shortcuts on web/Tauri/native; preserve every field, version and price-publication command.
- Existing business/location/membership APIs → clearer setup, searchable locations, edit drawers, grouped permission selection; preserve tenant scope, delegation rules and lifecycle safeguards.
- Existing transfer/sales queries and owning commands → browsable records and focused detail drawers; preserve server pagination, transitions, refunds and printing.
- Existing development accounts and authenticated domain APIs → additive multi-business/store/warehouse/product fixtures with stable stock idempotency keys. Never write stock projections directly or seed a production environment.
- Inventory card styles → whole-card hover/focus without title-only background; use shared semantic tokens and native pressed feedback.
- No migration, new dependency, settings persistence change or offline protocol change planned.

## Validation plan

Test grouped form value preservation, membership grants/scopes, forbidden operations,
record selection, additive seed reruns, real local workflows, relevant unit/browser
checks, types/lint/builds and available native runtimes. Preserve unrelated changes.

## Delivered (2026-10-22)

1. **Populated development workspaces:** `npm run db:seed:showcase` adds three demo businesses and stocks the existing development business as well. Across these four businesses it prepares 48 products with USD prices, eight additional stores/branches and sixteen additional warehouses. Zero-stock examples are intentionally left without an opening movement. The existing development owner receives membership in the new demo businesses; existing accounts, memberships, prices and balances are preserved. Both the normal API on 3100 and isolated audit API on 3191 now contain the fixtures.
2. **Product forms and prices:** web/Tauri and native forms group basics, images/codes, and category/inventory settings into collapsible sections. Closed sections preserve field values. Invalid required basic fields reopen their section on web. Editing puts the existing price shortcut first; publishing a price is prominent, with advanced variant/promotion commands in a disclosure. Prices still use the existing effective-price API; recorded sales are unchanged.
3. **Inventory cards:** title-only hover fill is removed; the whole card has semantic hover/focus feedback while selected styling is preserved. Native retains its existing whole-card pressed feedback.
4. **Business setup:** the shared-per-platform Add Business flow now confirms successful registration and offers location, company-profile and team-access setup steps. Existing owner assignment remains server-controlled. The platform directory can open an authorized management workspace from a detail drawer. Business Settings reuses the creation component and links to existing company branding, location and access screens. Consequential status/archiving controls are grouped separately; archive confirmation remains intact.
5. **Locations:** searchable list/grid views show name, code/type, parent store and status. Create/edit uses the established drawer. Scoped/archived read-only records open read-only details; write controls retain the existing permissions and scope checks.
6. **Permissions:** canonical role capabilities have readable labels. Custom grants are grouped by area with selected counts and retained checkbox values. Existing restrictions on delegation and store-scoped grants are unchanged. No new roles or permission grants were added.
7. **Transfers and receipts:** searchable, paginated list/grid collections replace document selectors. Transfers show reference, warehouse route, date and state; receipts show business-local date, receipt ID, currency-formatted total and status. Details open in drawers, retaining authorized transition/correction commands and printing. Opening a record never posts a transaction.

Existing unrelated workspace changes were preserved. Large location coordinators and the seed runner have explicit source-size review rationale.

## Remaining limits

Existing price publication is a separate effective-dated command after product metadata is saved; this preserves price history and transaction semantics. No single atomic product-plus-price API was invented. Transfers still expose existing storage/variant identifiers in advanced fields and use the existing bounded item lists. Invitations remain the existing onboarding mechanism; assigning a role requires an existing invited account. Selection remains local to loaded records and does not imply bulk mutations. Development fixtures deliberately have no fabricated image assets, payments, receipts or sales figures. Full device printing/scanning, Windows/iOS runtime checks, signed installers and exhaustive offline/financial mutation coverage remain outside this pass.
