# UI and POS follow-up — 2026-10-22

Implemented all seven requested changes using existing controls, without new dependencies.

- Moved desktop sidebar collapse/expand to the header. Mobile retains its existing navigation opener.
- Standardized profile/workspace chevrons at 20 px in the shared web/Tauri shell. Native already uses the same IconAction/NativeIcon sizing.
- Fixed POS warehouse selection when locations arrive after mount or authorized scope changes. Active unpriced SKUs remain visible under the currency filter; priced SKUs in a different currency remain filtered. Missing prices still fail server-side quote validation.
- Settings route navigation now uses the existing Radix/shadcn tabs treatment from inventory list/grid, with icons, selected state, keyboard navigation and horizontal scrolling. Native uses matching native icon tabs.
- Inventory and common record grids use circular corner selection, selected tint and border, without changing detail actions. Desktop unchecked selectors appear on hover/focus; touch selectors remain visible. Native uses compact accessible checkboxes.
- Added a Settings entry in web/Tauri and native profile menus.

## Scope and limitations

No API shape, schema, transaction calculation, permissions or preference storage changes. The only backend behavior change is retaining unpriced active products in POS results. Catalog pricing must still be configured before those products can be sold. No sample prices or stock were injected into the local application's business data.

Shared web changes reach macOS and Windows Tauri rendering. Windows execution requires a Windows/WebView2 host; iOS native execution requires a full Xcode/simulator environment. Neither is available. Full financial, offline/device and every-role audits were not repeated for these UI changes; prior audit evidence remains historical.

Common component usage and the live showcase are documented in `docs/development/common-components.md`. The impact map is `plan.md`. Screenshots and browser result JSON are alongside this report. Test databases are retained in `docs/qa/retained-test-databases.json`; no databases were reset or deleted.
