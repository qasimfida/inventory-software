# Security, data and offline rules

## Identity and authorization

- **SEC-001** [review] Invitation onboarding; operator-issued password recovery. Keep established password hashing, session expiry/renewal, rate limits and revocation. Never invent a successful email/SMS verification.
- **SEC-002** [review] Browser credentials use HttpOnly cookies with production Secure/SameSite and origin/CSRF checks. Mobile uses SecureStore; desktop credentials remain ephemeral in memory. Client environment variables are public.
- **SEC-003** [review] Every protected read/write, export, job, socket and retry resolves authenticated membership, tenant, permission and store/warehouse/resource scope. Client IDs, hidden controls and notification delivery grant no authority.
- **SEC-004** [review] Hide inaccessible routes/actions in UI; keep backend checks. Account/business changes, expiry, denial and explicit lock clear sensitive in-memory state. Browser tab hiding/focus is not a session lock: revalidate in the background without remounting an unexpired workspace; enforce expiry on return even if timers were suspended. Native background session locking remains unchanged. Do not reset user preferences to work around a session failure.
- **SEC-005** [review] Use scoped foreign keys/unique constraints, bounded queries and safe validation. Cross-business trade authorizes each party separately. RLS is not a substitute for existing application checks and must not be claimed universally active.
- **SEC-006** [review] Mutations commit source/projection/audit/idempotency/change records atomically where locally transactional. Authorize before replaying an idempotency receipt; reject a reused key with a different payload.
- **SEC-007** [review] Generic transports never automatically retry mutations. Protected retries retain their original ID and payload. An unknown response is not proof of failure; inspect/reconcile before creating a new operation.
- **SEC-008** [review] Log actor, scope, operation, reason and safe diagnostic context. Never log passwords, cookies, tokens, keys, payment secrets or unnecessary PII. Show actionable safe errors; keep technical correlation IDs secondary.
- **SEC-009** [review] Production uses validated config, verified database TLS, HTTPS, narrow CORS/CSP, bounded requests and durable abuse limits. CORS is not authorization. Seeds/mocks stay explicitly development/test-only.

## Stock and money

- **SEC-010** [review] LedgerCore owns immutable inventory movements and transactional balance projections. Preserve actor/time/source/reason, base-unit precision and movement references; never overwrite stock silently.
- **SEC-011** [review] Reservations, damaged stock, in-transit stock and physical on hand are distinct. Lock affected stock keys consistently; test concurrent allocation, partial transfers/receipts, counts and rollback.
- **SEC-012** [review] Counts reconcile against observations/revision and intervening movements. Transfers require both endpoints. Inter-business trade status does not post either party's stock/cash.
- **SEC-013** [review] Quantities use exact six-place decimal rules; money uses currency minor units. Preserve currency exponent, original units, rounding/tax/discount order. Never sum currencies or use binary floating-point financial totals.
- **SEC-014** [review] Prices/taxes/discounts on posted sales are immutable snapshots. Current product edits affect new quotes; checkout revalidates server-side. Display-currency estimates never affect transactions, settlement, original records or server calculations. An omitted selling-price tax input resolves the configured business rate (or zero), then stores that explicit rate; zero is an explicit override, not ongoing inheritance.
- **SEC-015** [review] AR/AP derive from obligations, credits and allocations. Prevent overpayment, over-return, over-refund and negative till cash transactionally. Return credits apply original cumulative rounding and reduce unpaid credit before cash refunds.
- **SEC-016** [review] Goods return, credit, refund and replacement sale are separate linked facts. Damaged returns do not increase sellable stock; non-restockable returns do not increase stock. Closed shifts and posted journals are immutable.
- **SEC-017** [review] Accounting is limited balanced source posting, not statutory accounting/valuation. Source uniqueness is separate from request identity. Reversing a journal does not reverse its sale/stock/payment.

## Posting boundaries

- **SEC-018** [review] Confirmed event: Online order acceptance (future); Stock: Reserve real sellable quantity only; Money / journal intent: No sale revenue or cash; backordered remainder unallocated
- **SEC-019** [review] Confirmed event: Cancel unfulfilled remainder; Stock: Release hold once; Money / journal intent: Refund any advance separately; no fictitious stock increase
- **SEC-020** [review] Confirmed event: Physical dispatch/pickup; Stock: Deduct fulfilled goods and consume hold once; Money / journal intent: Recognize fulfilled sale/AR; debit settlement/AR, credit net revenue/tax
- **SEC-021** [review] Confirmed event: Cash physically collected; Stock: None; Money / journal intent: Open-shift cash receipt; debit cash, credit AR or customer advance
- **SEC-022** [review] Confirmed event: Confirmed courier/bank collection; Stock: None; Money / journal intent: Debit relevant clearing, credit AR/advance; no till cash
- **SEC-023** [review] Confirmed event: Advance applied at fulfillment; Stock: No extra deduction; Money / journal intent: Debit advance, credit AR; no duplicate revenue
- **SEC-024** [review] Confirmed event: Clearing remitted to bank/till; Stock: None; Money / journal intent: Debit bank/cash, credit clearing; no second customer payment/revenue
- **SEC-025** [review] Confirmed event: Order complete; Stock: None beyond fulfillment; Money / journal intent: No extra posting
- **SEC-026** [review] Confirmed event: Authorized return received; Stock: Disposition-specific movement once; Money / journal intent: Linked credit: reverse revenue/tax into settlement/AR
- **SEC-027** [review] Confirmed event: Approved refund actually paid; Stock: None merely from payment; Money / journal intent: Debit settlement/advance, credit actual cash/bank/clearing
- **SEC-028** [review] Confirmed event: POS checkout; Stock: Existing immediate handover movement; Money / journal intent: Existing sale/payment sources, once each
- **SEC-029** [review] Confirmed event: Offline captured sale; Stock: Provisional local evidence; Money / journal intent: No confirmed server posting until authorized successful sync
- **SEC-030** [review] Partial events cover only confirmed portions. Future online source posting must persist a durable intent with source/audit effects; pending journals are not posted journals. These posting rules preserve design decisions, not a claim that guest fulfillment or clearing is implemented.

## Offline contract

- **SEC-031** [review] Only prepared, encrypted, bounded **cash sales**, carts and catalog/price snapshots may operate offline. Credit, refunds, approvals, purchasing, counts, transfers and online-store administration require online authority.
- **SEC-032** [review] Policy defaults off; grants bind account/business/device/warehouse/currency/shift/access fingerprint/policy/immutable price snapshot. Preserve configured 5–480 minute lease, cash/quantity/discount limits and changed-price policy.
- **SEC-033** [review] Current preparation is bounded to 250 active variants, one currency and warehouse-root stock. Cached stock is an allowance, never a global reservation; server shortages stay conflicts.
- **SEC-034** [review] Vault is an authenticated encrypted document: AES-256-GCM, random 96-bit nonce, independent salt and PBKDF2-HMAC-SHA256 (600,000 iterations). No account password, session token or plaintext customer profiles. Separate passphrase loss has no recovery backdoor.
- **SEC-035** [review] Web uses IndexedDB; Tauri and native use transactional SQLite WAL adapters. Origin/account/device partitions, compare-and-swap writes, atomic cart/outbox and projection/cursor commits remain mandatory.
- **SEC-036** [review] Lock/background clears in-memory keys. Expiry blocks new sales without deleting pending evidence. Detect backward-clock movement; hostile device clocks remain a known limitation. Revocation discovery is bounded by the original lease, not instantaneous offline.
- **SEC-037** [review] Upload reauthorizes current scope/policy/shift/stock and operation time; normal grace is 24 hours for in-grant sales. Older/revoked/conflicting records require authorized reconciliation, not deletion or recreated sales.
- **SEC-038** [review] Batches max 20, durable atomic claims before I/O, stable IDs/hashes, exponential jitter backoff capped five minutes, eight failures require review. Late replies never downgrade confirmed results.
- **SEC-039** [review] Schema migration/backup/restore must preserve pending work; unknown/tampered versions fail closed. Backup encrypted envelopes and consistent SQLite WAL state. Never advise clearing storage with unsynced sales; outbox retention cap is 1,000 records.
- **SEC-040** [review] Readiness recovery triggers eligible sync; polling/backoff recovers missed events. Progress counts server confirmations, not bytes/network availability. Pending/sending/synced/rejected/conflict remain distinct with reviewable receipts.
- **SEC-041** [review] Offline shell service worker caches public app assets only, never private API/auth/analytics. Development Vite and Expo web export are not proof of offline browser restart. Do not force updates mid-checkout.
- **SEC-042** [review] Revision polling/WebSocket tickets are scoped invalidation hints, never command channels or confirmation. Reconnect rereads authoritative data; delta cursors bind scope/currency and commit with cache updates.

## Public and analytics boundaries

- **SEC-043** [review] Published reads expose allowlisted fields only, never costs/suppliers/private inventory/customer data. Guest writes/event ingestion require distinct implementation, narrow guards, stable identities and abuse limits. Status tokens must be random, digest-stored, bounded, revocable and scoped to minimal status; redact URL/log/referrer exposure. Staff authority cannot be inherited by a guest endpoint.
- **SEC-044** [review] Analytics may retain an authorized, timestamped **in-memory** view during transient failure only until session expiry/lock. Partition by account/business/permissions/query/currency/timezone; clear on denial, switch, logout, explicit lock, native background or restart. Browser tab hiding may retain this bounded in-memory view until session expiry; it does not authorize offline analytics or persist data. No analytics in SQLite, IndexedDB, vaults, backups or service worker. Intended net reporting counts return credits once, not both credit and refund, with business-timezone/DST boundaries and separate currencies.
- **SEC-045** [review] Notification inbox removal sets `business_deliveries.dismissed_at`; audit events and delivery evidence remain. Read/unread/removal revalidate recipient, tenant, permission and location scope. Actor emails in notifications and audit history require `users.read`. Member removal archives only that business membership; customer archival retains transactions and rejects outstanding exposure. Never present either operation as global account or ledger deletion.
- **SEC-046** [review] Rich product/online descriptions keep the existing string field: legacy values are plain text; `<!--inventory-description:v1-->` marks allowlisted HTML. Contracts normalize marked writes; `descriptionText` drives readiness, and renderers consume parsed nodes. Only paragraphs, emphasis, lists and HTTP(S)/mailto links survive; scripts, embeds, arbitrary attributes and unsafe links do not. Do not render this field as unrestricted HTML. The existing 2,000-character serialized limit applies; no migration or legacy rewrite is needed.
- **SEC-047** [review] Quill 2.0.3 has an open HTML-export advisory ([GHSA-v3m3-f69x-jf25](https://github.com/advisories/GHSA-v3m3-f69x-jf25)). Its export is untrusted: sanitize it before persistence and render parsed allowlisted nodes, never exported HTML directly. Keep those protections and review upstream fixes; dependency audit is not clean.

## Accepted product decisions

- **SEC-048** [review] Decision: PO sending; Rule / consequence: Keep `ordered`; optional sent time/method, UI “Ordered / Sent”; no new state or stock/cash effect.
- **SEC-049** [review] Decision: Prices; Rule / consequence: No named price lists. Storefront uses the existing default-store resolver and explicit online overrides; never create a parallel calculator or change POS price through an online override.
- **SEC-050** [review] Decision: Adjustment reasons; Rule / consequence: Built-in codes plus optional tenant custom codes; preserve historical reason snapshots and existing free text.
- **SEC-051** [review] Decision: Refund approvals; Rule / consequence: Cumulative per-sale, per-currency thresholds through the approval queue; absent policy requires approval. No self-approval or split-request bypass. Execution revalidates independently. Do not assume every refund path implements this yet.
- **SEC-052** [review] Decision: Undo; Rule / consequence: Authorized, idempotent linked compensation; never erase committed stock, money or audit history.
- **SEC-053** [review] Decision: Public API; Rule / consequence: Separate published-only projection, not internal catalog controllers. Narrow guest commands and event ingestion require separate guards and abuse budgets before implementation.
- **SEC-054** [review] Decision: Sellable stock; Rule / consequence: On hand − reserved − damaged − buffer, per SKU and allocation pool; buffer once, transit separate. Backorders are identified unallocated demand, not fictional holds.
- **SEC-055** [review] Decision: Readiness; Rule / consequence: Content/price failures auto-delist; zero availability remains active as Sold out or hidden by policy. Stock is not a content blocker.
- **SEC-056** [review] Decision: Payments; Rule / consequence: Pickup/COD/manual transfer design only; COD unpaid until confirmed collection, transfer uses clearing. Card providers disabled. Configuration does not imply guest checkout exists.
- **SEC-057** [review] Decision: Posting; Rule / consequence: Order, payment, fulfillment and journal events are distinct; see [integrity](security-and-data.md#posting-boundaries).
- **SEC-058** [review] Decision: Analytics; Rule / consequence: Online-only, in-memory cached/as-of views. Intended shared POS/online aggregation uses business timezone and net returns; do not describe legacy UTC/gross queries as migrated without tests.

- **SEC-059** [review] Integration/rollback qualification uses an explicitly disposable database. A downgrade that cannot represent valid newer records must block release planning; never delete records, weaken constraints or skip rollback assertions merely to obtain passing redesign checks.

- **SEC-060** [review] Quantities and conversion ratios use positive exact decimal strings with at most six fractional digits; conversion results exceeding precision fail rather than round. A 0.333 quantity is not exact one-third; a 1/3 ratio only succeeds for representable resulting quantities. Conversion units must share the base dimension (a tin measured in liters is volume); ratios/base units remain immutable. Per-product precision and indivisible-pack rules do not exist and require explicit domain/API design before offering controls. Default-variant identifiers remain owned by the product editor.

- **SEC-061** [review] Self-hosted product-photo uploads require business-wide products.write, strict MIME/signature/base64/512 KB checks, opaque random filenames, tenant directories, audit metadata and a 1,000-file/business quota serialized by the business lock. Public GET serves raster bytes only with nosniff/sandbox and rate limits, never listings or business metadata. Upload URLs are public capabilities; no sensitive documents. Replacement/removal unlinks product references, never silently deletes files. Files retain embedded metadata; operators must consider photo privacy.

- **SEC-062** [review] Import preflight is read-only and tenant/permission scoped; it does not reserve SKUs or guarantee commit. Final creation rechecks existing constraints and posts products, 0%-tax selling prices, optional Each-unit opening stock and audit/idempotency receipts in one transaction. No partial skip/update mode. Mapping edits/deletion use version checks; deletion removes template metadata only and retains its audit. Source data remains transient client memory, not offline persistence. Apply migration 1795500000000 before template APIs; rollback removes saved templates and is only appropriate for disposable tests or reviewed recovery.

- **SEC-063** [review] Staff directory GET `/businesses/:businessId/operations/staff` returns employment-only fields, never salary/currency/costs. Directory, compensation detail and operations remain business-wide `users.write`; managers, cashiers, viewers and location-scoped members cannot read salary. `/salaries` reuses existing compensation/cost capabilities; required nonnegative minor-unit base salary and supported currency remain the only compensation fields. No frequency/effective-date/payroll calculations. Staff saves are versioned; audit/notification metadata excludes compensation amounts.

- **SEC-064** [review] FX is display-only: bounded HTTPS provider response, no redirects, 3-second timeout, secret App ID server-side, exact rate literals parsed to decimal strings and BigInt cross-ratios; round once half-away-from-zero to target currency exponent. No conversion chain or sum across currencies. Snapshot expires 24 hours after provider publication; missing pairs/expired rates show originals. Offline may use a labeled unexpired in-memory rate snapshot; restart has none. Financial/analytics persistence and authorization remain unchanged. Authenticated rate GET contains public market metadata only; no tenant records or provider credentials.
