# Central database migrations

Authentication accounts, invitations, sessions and rate-limit buckets are introduced by the first migration. The second migration adds businesses, memberships, stores, warehouses, terminals and audit events; see [organization management](../../../docs/development/organization-management.md). Subsequent migrations add permissions, operation receipts, catalog/pricing, inventory, purchasing, storage, transfers and commerce. The current 14 migrations end with customers/credit (`1793400000000`), sales (`1793500000000`), cash shifts (`1793600000000`) and sale returns (`1793700000000`). No future business tables are pre-created. Historical payments predating cash shifts retain a nullable shift reference; no fictitious opening cash is backfilled. New payments require an open shift in application commands. `node-pg-migrate` owns the `schema_migrations` metadata table and serializes migration execution with its advisory lock. See [migration workflow](../../../docs/development/migrations.md) before creating or applying SQL migrations.
