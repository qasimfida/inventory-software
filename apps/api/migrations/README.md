# Central database migrations

Authentication accounts, invitations, sessions and rate-limit buckets are introduced by the first migration. The second migration adds businesses, memberships, stores, warehouses, terminals and audit events; see [organization management](../../../docs/development/organization-management.md). Subsequent migrations add permissions, operation receipts, catalog/pricing, inventory, purchasing, storage, transfers and commerce. There are now 24 migrations, including offline synchronization (`1793800000000`), stock counts (`1793900000000`), damaged receiving (`1794000000000`) and supplier settlement (`1794100000000`). Stage 4 migration `1794200000000_security_reliability.sql` adds hashed recovery codes, revocable offline grants and currency-bound sync cursors. It invalidates only ephemeral existing cursors to force full refresh; it preserves leases, pending operations and ledger records. No future business tables are pre-created. Historical payments predating cash shifts retain a nullable shift reference; no fictitious opening cash is backfilled. New cash payments require an open shift in application commands. Supplier invoice obligations retain their original amounts; past supplier settlements are not guessed. See [Stage 3 rollout](../../../docs/development/stage-3-workflows.md) for payable policy and mixed-condition returns. `node-pg-migrate` owns the `schema_migrations` metadata table and serializes migration execution with its advisory lock. See [migration workflow](../../../docs/development/migrations.md) before creating or applying SQL migrations.

Command 25A migration `1794300000000_settings_security.sql` adds versioned personal preferences/policies, recognized installation signals, immutable security events, durable notification delivery/inbox and restricted diagnostic retention. Existing sessions retain nullable device references; users and business transactions are preserved. Apply before API startup. See [Command 25A rollout](../../../docs/development/command-25a.md).

Migration 21 `1794400000000_security_session_references.sql` adds historical non-secret session IDs to security events. No foreign key intentionally prevents expired-session pruning from being blocked by permanent audit references.

Migration 22 (`1794500000000_reports_notifications.sql`) adds durable business notification deliveries, tenant-bound audit/recipient references and report period indexes. It does not backfill notifications or rewrite inventory/financial facts. Apply it before the updated API begins serving audit-producing business operations. Down removes these deliveries/indexes and their additional audit identity constraint; use rollback only in disposable/development environments when that loss is acceptable. Stage 5 validation is in `docs/development/stage-5.md`.

Migration 23 (`1794600000000_trading_accounting.sql`) adds bilateral consent/orders and immutable balanced journal entries with accounting periods. It does not backfill historical accounting or alter stock/cash sources. Posted journal validation uses deferred PostgreSQL constraint triggers. See [Stage 6](../../../docs/development/stage-6.md) before enabling posting. Production downgrade is prohibited; use backup and reviewed forward repair.

Migration `1794700000000_operational_costs.sql` adds tenant-scoped staff records, salary/expense obligations and append-only payments. It does not backfill payroll, alter stock, or post cash/journals. Salary and expense authorization remains owner/platform `users.write`; existing store-scoped roles do not gain access.

`1794800000000_live_catalog.sql` adds short-lived hashed WebSocket tickets and a post-commit notification trigger on existing sync revisions. It does not rewrite prices or stock. Deploy the migration before enabling the new API; forward WebSocket upgrades as documented in [live pricing](../../../docs/development/live-ui-refinement.md).
